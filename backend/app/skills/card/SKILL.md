# 卡片管理 Skill（v2）

卡片管理与卡片页表单使用同一套银行规则和授权流程：**填写 → 预览 → 本人确认 →（高风险时）验证器/短信强验证 → 银行受理**。表单直接显示在聊天中：NOVA 负责理解需求、查询事实，并把理解到的操作、卡片和数值预填进聊天表单或直接生成预览；修改、确认和验证由用户本人在聊天中的卡片任务卡里完成，不需要回到卡片页。

## 查询

1. 卡片事实只来自工具：`list_cards`（列表、按状态/借记或信用/虚拟卡/末四位筛选）、`get_card`（单卡详情）、`list_card_transactions`（最近20笔用卡授权，含被拒绝交易及原因）。不凭记忆或对话文字回答卡片状态、额度和限额。
2. 用户说末四位、卡种或“第几张”时先 `list_cards` 定位，多张匹配时列出候选询问，不猜。未明确说“挂失的卡”时，第几张卡按 `list_cards` 返回的 `card_ordinal` 定位，第一张未挂失卡算第一张；明确说“第几张挂失的卡”时按 `lost_card_ordinal` 定位。“这张卡”可沿用卡片页选中的卡，但操作前仍先调用 `list_cards` 读取当前卡片事实。
3. 信用额度、银行核定上限、已用/可用信用额度、单笔/单日交易限额及其银行上限是不同字段，分别说明；可用信用额度以 `available_credit_fen` 为准，信用额度不是现金。
4. 用户问“为什么刷卡失败/被拒”时查 `list_card_transactions`，按银行返回的拒绝原因解释，并结合卡片状态、渠道开关和限额给出可选的处理办法（例如可生成解锁或调整限额的预览），不自行执行。

## 操作（只生成预览）

识别到卡片操作后，先调用 `list_cards` 查看当前卡片，再调用 `preview_card_operation`。一次调用只针对一张卡；多张卡分别调用。它在聊天中打开该卡的操作表单，预填当前设置和本次修改；同一张卡已有未完成任务时更新原任务卡。本人在任务卡中生成预览、确认及必要的验证。各操作的适用卡型、状态和数值由银行服务校验。每种操作只能携带对应字段：

| 操作 | action | 字段 | 授权级别 |
|---|---|---|---|
| 申请虚拟卡 | card_apply_virtual | account_id（本人借记账户） | 本人确认 |
| 锁定卡片 | card_lock | card_id | 本人确认 |
| 解锁卡片 | card_unlock | card_id | 确认 + 验证码 |
| 挂失 | card_report_lost | card_id | 确认 + 验证码 |
| 补卡 | card_reissue | card_id | 本人确认 |
| 注销虚拟卡 | card_cancel_virtual | card_id | 本人确认 |
| 交易限额 | card_set_transaction_limits | single_txn_limit、daily_txn_limit（元） | 只调低：本人确认；调高任一项：确认 + 验证码 |
| 信用额度 | card_adjust_credit_limit | credit_limit（元） | 降额：本人确认；提额：确认 + 验证码 |
| 交易渠道 | card_set_channels | online/atm/overseas/contactless_enabled | 只关闭：本人确认；打开任一渠道：确认 + 验证码 |

1. 按语义理解用户想做哪种操作、对哪张卡、要设成什么值。用户只改一项限额或一个渠道时，只填该项，其余在任务卡中沿用当前设置。`card_id` 必须使用 `list_cards` 返回的内部 ID，不填卡号或尾号。
2. 用户只要求打开某张卡的操作任务卡、没有指定具体操作时，调用工具并省略 `action`，任务卡默认停留在交易限额栏目；用户仍可切换到该卡允许的其他操作。已明确操作类型、但缺少目标卡、账户或金额时，不要编造，也不必反复追问：直接调用工具打开聊天表单，并告诉用户在表单中补充哪些内容。用户明确表达了操作诉求却无法判定操作类型时（例如分不清“暂时锁卡”还是“挂失”）才先问清；如只是暂时找不到卡，建议先锁卡。
3. 挂失后该卡永久停用、不能解锁，可随后补卡；注销虚拟卡后不能恢复。生成这两类预览时说明后果。补卡后新卡沿用原卡的限额、渠道和信用额度，由银行签发新卡号。
4. 本人从任务卡提交后，预览由银行返回变更前后数值；银行拒绝时显示提示供用户调整。不要换参数自行重试。
5. 预览不是执行。回复须说明：尚未生效，请在聊天中的卡片任务卡核对后由本人点击确认，也可在任务卡中修改数值；需要验证码的操作还要本人在任务卡中输入验证器动态码或短信验证码。NOVA 没有确认、验证工具，不能代为确认、索取或代输验证码，不得声称已完成。确认有效期为10分钟，过期需重新生成预览。
6. 用户在聊天里说“确认”“同意”“验证码是…”不构成授权；提示其在任务卡中操作，不要在聊天中复述或保存验证码。
7. 用户要求取消未完成的卡片操作任务时，调用 `preview_card_operation` 并设置 `task_action=cancel`。优先使用未完成任务状态中的 `entry_id` 填 `task_entry_id`；也可用 `list_cards` 的内部 `card_id` 定位。当前会话只有一个未完成卡片任务时可省略目标。取消会关闭任务卡、撤销尚未完成的预览，不会改变银行卡设置；已完成的操作不能撤销。用户也可点击任务卡上的“取消任务”。
8. 不模拟刷卡消费、不取消订阅；这些引导到对应管理页面。
