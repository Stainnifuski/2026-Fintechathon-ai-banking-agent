# AI Banking Agent

面向银行业务的 AI Agent 比赛演示项目：通过自然语言理解意图、规划任务，在风险分级和用户授权后调用模拟银行，展示可核对的执行结果。后端 FastAPI，前端 React/TypeScript，数据库支持 SQLite 与 PostgreSQL。

> 账户和资金均为虚构；默认采用真实基金与官方规则参考的模拟银行理财混合研究池（目标44＋16，可扩展），另支持全量基金目录和池外缓存，不连接真实银行交易。理财高风险环节使用明确标注的点击模拟授权，不采集或验证指纹、人脸、短信码或支付密码，不宣称已实现真实多因素认证。

## 场景与当前能力

| 场景 | 已实现 | 当前边界 |
|---|---|---|
| 智能转账 | 姓名/手机号转账、备注、多轮修改、定时转账、AA收款及原号恢复 | 聊天处理即时人民币转账；定时/AA走表单；可配置外部模型 |
| 账单分析 | 月度/年度报告、分类趋势、异常提示、流水下钻及只读问答 | 默认离线，可配置模型理解 |
| 理财操作 | 全量基金搜索／池外缓存、44真实基金＋16官方规则模拟理财目标池、产品及组合分析、版本化知识与8宏观指标、DeepSeek多轮、本人评估、申赎/配置/调整/异步结算 | 真实行情仅研究；可信页面确认和模拟授权；日更需显式启用 |
| 订阅管理 | 已有订阅记录及相关操作 | 范围以现有接口与测试为准，不等同完成全部自动识别能力 |
| 卡片管理、跨场景联动 | 后续范围 | 不声明已完整交付 |

比赛要求至少覆盖3个核心场景，并重视任务完成、安全和交互体验。当前功能入口、限制和证据按上表及下列文档核对；网页演示不自动等同已完成原生APP或IM渠道验收。

## 快速启动

已有 `.env` 时保留原文件；首次运行复制 `.env.example`，设置独立的 `JWT_SECRET` 与 `INTERNAL_BANK_TOKEN`，不要提交密钥。默认离线无需模型密钥。

```bash
cp .env.example .env
docker compose up --build
```

前端：<http://localhost:3000>；健康检查：<http://localhost:8000/health>；API：<http://localhost:8000/docs>。本地SQLite、Windows启动及故障排查见[运行指南](运行指南.md)。当前无需Redis。

演示用户：张三 `13800000001`，密码 `password123`；仅用于虚构演示。升级已有数据库先备份并遵循[理财迁移交接](docs/wealth/handoff.md)，不要删除数据卷或混跑旧扣款代码。

**理财授权配置**：默认 `WEALTH_DEMO_VERIFICATION_ENABLED=true`，普通演示数据库即可使用。已有 `.env` 若保留旧的 `false`，改为 `true` 后重启后端。无需另建3010/8010服务或命名为wealth-demo的数据库。管理员加速时钟仍需独立演示库和专用开关。

离线回归初始化合成60份额：`docker compose exec backend python -m app.services.bank.wealth_data_cli init --user-id U001`，在理财“数据集、产品研究与宏观背景”选择新资金上下文。原legacy账本和旧订单保留。模型配置与独立日更命令见[数据说明](docs/wealth/data_sources.md)。

## 体验与风险授权

- 转账：输入“给手机号13800000002转300元，备注房租”，核对收款人、金额和风险等级，再操作任务卡。
- 账单：进入账单分析查看报告、异常和流水，使用独立只读问答入口。
- 理财：查看产品→本人评估→生成订单或配置方案→确认披露→点击“通过支付密码形式授权（模拟）并提交”→查询受理、计价和到账。详细操作见[理财演示指南](docs/wealth/demo.md)。

产品风险R1—R5、用户风险承受能力和操作权限等级是三个不同概念。项目沿用绿色查询自动执行、黄色明确确认、红色高风险授权的分级；模拟点击展示红色授权交互，不能作为真实强验证证据。现有转账TOTP未在本次改动中替换。后续理财接入3号统一高风险授权接口，统一接口仍可使用模拟提供者，无需开发真实生物识别输入。

模拟授权仍要求登录主体、逐笔披露确认、参数与版本绑定、有效期、审计和幂等。AI不能代替用户确认，聊天“好的”不直接扣款。等级展示方案及接口衔接见[模拟授权说明](docs/wealth/simulated_authorization.md)。

## 测试与比赛交付

```bash
python -m pytest tests -q
cd frontend
npm ci
npm run build
```

PostgreSQL并发验收需单独配置测试库，未配置时相应用例会跳过；具体环境、日期、通过/跳过数量以每份验证记录为准。历史报告不代表当前提交已在全部环境重新验证。真实模型测试不属于默认离线测试。

提交材料应包含作品简介、架构与算法说明、安全设计/自评、部署说明、测试用例和答辩材料；视频按最终赛事口径准备。安全自评必须披露模拟授权未实现真实MFA，不把演示替身写成真实认证或声称已获得赛事豁免。功能与数据来源、开源引用在页面、仓库及比赛材料中保持一致；v1.2数据、分析、知识与模型升级的实际验收及限制见下级文档。

### 全量基金与混合预加载池

目录搜索不限预加载数量；默认最新混合快照逐项标识真实基金或模拟银行理财。可调整清单、官方规则与模拟调整、按需开关、初始化及日更命令见[全量目录与预加载指南](docs/wealth/preload_and_directory.md)。真实基金缺审核规则仅研究，全部资金、成交与点击授权仍为模拟。

## 文档与AI协作规范

1. README只维护项目定位、当前能力、快速入口、安全边界和文档导航；配置细节、接口字段、数据库设计及逐次测试日志放入对应下级文档，禁止不断追加重复“本轮完成”段落。
2. 功能变更同时更新对应契约、运行说明及有日期的验证记录。区分已实现、模拟替身、计划中和未验证，不复制旧测试数字作为当前结论。
3. 开始修改前阅读README及相关模块文档；早期 `.cursorrules` 中的规划/示例与现有实现有差异时，核对代码和当前契约，不为匹配旧规划重写项目。
4. 保留他人改动和现有数据。推送、创建PR及最终合并前重新获取最新 `origin/main`，比较并整合变化，复验受影响流程；不得强推覆盖队友提交。远端发布按用户授权执行。
5. 不提交密钥、个人数据、运行数据库、备份或默认抓取的完整真实数据集；保留来源/许可证说明，禁止复刻第三方银行界面和声称第三方背书。
6. 更改3号公共授权应同步公共契约；当前理财模拟适配点见专门说明，不把3号未来接口写成已存在，也不让模型调用授权签发工具。
