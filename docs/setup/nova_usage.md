# NOVA 使用指南

更新：2026-10-25。NOVA 可查询本人银行与生活服务信息、生成卡片和账单修改确认卡，也可在聊天中建立多笔即时人民币转账草稿及待确认计划。修改和交易以本人在对应可信卡片中的确认结果为准。

## 打开、切换和选择

登录普通银行用户后点击“问 NOVA”。桌面端在右侧与业务页面并排显示；宽度1100px及以下采用上下分区，各自滚动。打开时可继续操作页面，点击顶部按钮或面板“×”收起；切换业务页面保持对话。回答支持标题、加粗、列表和可横向滚动的表格。

NOVA 面板顶部可新建对话和切换历史对话。对话与转账任务绑定同一会话 ID；刷新或在其他设备登录后可从银行 API 读取本人历史并恢复该会话的任务卡。会话和消息存于银行数据库，消息正文使用 AES-GCM 加密；完整手机号和银行卡号在历史展示及模型上下文中隐藏。浏览器不再发送历史消息，NOVA 从银行侧读取当前会话的上下文。首次部署前应配置稳定且独立的 `NOVA_CONVERSATION_KEY`，更换密钥会使既有历史无法解密。请求使用发送时的页面状态；历史中的工具调用详情不保存，查询记录仅随本次响应返回。

回答先显示处理和工具查询进度，业务正文在后端根据实际结果生成后展示。未经核验的模型增量不会先显示。正文保留对象、金额单位、查询范围、截止时间、模拟标识和失败提示；界面显示“依据后端结果生成”或“部分结果未核实”等状态。保存到对话历史的是同一份正文。模型生成错误金额或无依据结论时不重试资金操作，改为展示可核验结果或补充提示。接口见 [流式接口](../contracts/NOVA页面上下文与只读工具_API_v0.1.md#流式接口)，边界见 [幻觉防护](../security/hallucination_guard.md)。

## 当前查询范围

账单页自然语言入口统一进入 NOVA，使用当前功能、已应用筛选和选中对象。工作台有六个一级页签，二级功能在同页折叠展开；手操草稿在页签与区块切换间保留。预算月份和预测账户独立于历史报告筛选。支持分类/标签、预算、异常核对、商户整理、周期计划与基准预测保存；模型只生成15分钟有效的确认卡，按字段展示修改前后，本人点击后才保存并刷新页面。聊天中的“确认”不能代为保存，不涉及转账、退款或真实扣费。完整工具及接口见 [NOVA 账单洞察接入契约](../contracts/NOVA账单洞察_API_v1.md)，布局与监管定位见 [账单工作台](../frontend/bill_workspace_20261025.md)。

后端业务查询与卡片预览工具如下；此外注册 `declare_goal_plan` 用于多目标结构化规划，`manage_transfer_request` 用于受控转账任务管理：

| 信息 | 工具 | 数据与口径 |
|---|---|---|
| 现实时间 | get_current_time | 默认北京时间，可指定IANA时区 |
| 本人账户概览 | get_financial_overview | 模拟银行；普通savings现金小计与当前授权范围AssetSummary分别返回；首页/理财页总资产使用后者，包含持仓与赎回应收，冻结不重复加 |
| 月度/年度账单 | get_bill_analysis | 模拟银行；完整统计不受流水分页影响 |
| 已完成流水列表/详情 | list_transactions、get_transaction | 模拟银行；本人账户归属校验 |
| 本人卡片列表/详情 | list_cards、get_card | 模拟银行；脱敏卡号、状态、限额/上限、已用/可用信用额度、有效期、渠道开关，信用额度不等于现金 |
| 卡片操作预览 | preview_card_operation | 模拟银行；与卡片页同一套校验和定级，只生成待确认单，不执行 |
| 本人订阅列表/详情 | list_subscriptions、get_subscription | 模拟银行；周期金额、计划扣费、取消状态，汇总为预计月费而非实际扣款 |
| 本人日历范围/名称搜索/详情 | list_calendar_events、search_calendar_events、get_calendar_event | 本人保存日历，来源user_calendar；全天按原日期，重复规则按窗口展开 |
| 两店商品列表/详情报价 | list_shop_products、get_shop_product | 模拟店铺；当前目录价，数量报价不表示下单 |
| 本人店铺订单列表/详情 | list_shop_orders、get_shop_order | 模拟店铺；下单价格快照，银行付款事实的只读状态投影 |

日历查询范围最多62天，重复活动详情默认未来30天，窗口内无发生只表示该窗口没有安排。名称搜索检索全部保存的标题/地点，不受当前月份限制。列表分页并说明总数；长活动备注可分段读取。

店铺付款状态按银行记录投影，不写回订单或账务。COMPLETED表示模拟银行付款成功，不表示配送；REFUNDED表示整单退款。页面尚未刷新时可能仍显示旧状态，可刷新店铺页面核对。缺付款记录时不能确认已支付。商品库存、配送、营业时间、真实门店地址和优惠未提供。

卡片及订阅已接入查询；卡片操作（申请虚拟卡、锁卡/解锁、挂失、补卡、注销虚拟卡、交易限额、信用额度、渠道开关）可由 NOVA 生成预览，回复下方出现“去卡片页核对并确认”，点击后在卡片页由本人确认，红色操作还需验证码。NOVA 不能代为确认或输入验证码。转账任务可在 NOVA 聊天窗口的任务卡中核对、确认并完成必要验证；口头“确认”不会扣款。理财已接入 manage_wealth_request：可在NOVA卡片内查询、推荐、规划、申购和赎回。风险问卷由本人作答，申购和赎回各自独立确认及MFA；其他操作使用已有工作台。当前能力不等于跨场景交易总DAG。

## 聊天转账

已保存联系人或本人已完成转账历史可用称呼加金额发起；Agent 仍会重新核验当前可用收款账户。新收款人需要姓名、完整手机号或完整16位模拟银行卡号及金额。信息不全时会保留草稿并追问；同名或多账户时按脱敏候选选择。转账任务卡显示在 NOVA 面板的聊天回复下方，已知字段会填入卡片，完整收款号码只显示尾号。可直接在卡片编辑并保存，也可选中任务后继续聊天，让 NOVA 补充字段；点卡片右上角叉号会取消该任务。信息齐全后在卡片核对金额、收款人、付款账户及风险等级，点击“确认转账”；高风险任务需在卡片输入 TOTP 或短信验证码。只说“转钱”会先显示缺收款人和金额的草稿，聊天文字本身不会扣款。

“把我银行卡里一半的钱转给赵六”会保留为转账草稿，不再报金额格式错误。只有一张可用现金账户时，NOVA 从银行接口读取该账户可用余额并向下取半到分；有多张时先选择付款账户。卡片显示具体金额及计算依据，首次生成银行计划时固定金额。收款人未在本人联系人或历史记录中时，仍需补充完整手机号或银行卡号。

“给倒数第六笔转账的人转相应的钱数”会先查询本人已完成流水并按时间倒序定位第六笔 `transfer_out`，再把该流水 ID 作为受控历史引用交给转账工具。收款账户和原金额由服务端从本人账本重新读取并核验，模型展示的人名或金额不能直接成为转账参数；最终仍只生成待本人核对的任务卡。

接口和请求幂等要求见 [NOVA 转账任务接口](../contracts/NOVA转账任务_API_v0.1.md)。

订阅列表默认包含已取消项；预计月费仅汇总筛选后所有分页的生效、月度、人民币订阅，不受当前页大小影响。计划扣费时间不表示已扣款或一定自动执行。卡片可用信用额度以银行返回的 available_credit_fen 为准。

接口与字段分别见 [基础工具与页面上下文](../contracts/NOVA页面上下文与只读工具_API_v0.1.md)、[时间](../contracts/NOVA时间查询_API_v0.1.md)、[日历](../contracts/NOVA日历查询_API_v0.1.md)、[店铺](../contracts/NOVA店铺查询_API_v0.1.md)、[卡片/订阅](../contracts/NOVA卡片与订阅查询_API_v0.1.md)。

## 模型与离线模式

共用根目录.env的LLM_*，默认服务只需配置一次LLM_API_KEY；LLM_MODE=auto有有效配置时启用模型，无配置时使用有限离线规则，offline全局关闭外部模型。LLM_MODE=model要求有效配置。详细配置见 [统一模型配置](model_configuration.md)。不要把密钥写入前端或提交到仓库。

模型模式采用分层编排：先输出严格结构化路由，单一目标直接进入 ReAct，多个独立目标（含同一业务的多个操作对象）或有条件依赖时同时生成 Goal Plan，再按目标依赖调用工具。单笔转账只向 ReAct 暴露转账管理工具并要求调用；相同调用连续三次会提前熔断，不再一直耗尽总步数。调用转账工具后，专用转账子模型会同时看到当前会话完整脱敏历史、本轮原文、页面提示、结构化 Goal Plan、本轮此前工具结果、可信历史引用和全部未终结任务摘要，并自行决定要新建或调整几笔任务；完整号码在发送前隐藏，历史与页面只用于理解指代，本轮工具结果可作为规划证据，但都不是授权。批量转账的高层 Goal Plan 不替代这一判断，Task Manager 仍会复核任务归属、原文字段、账户和金额。离线模式不提供 Goal Plan，也不提供这种自主任务数量判断。

离线支持有限的北京时间、资金/账单、常用日历日期/名称、卡片/订阅列表与页面选中详情、当前店铺目录/选中商品报价/本人订单查询，以及明确句式的即时转账和逐笔补充，页面明确标记“离线规则”。复杂表达、跨轮推理、其他时区时间、商品价格条件筛选和两店比较需要模型。配置了模型但调用失败时会显示错误，不自动伪装成离线成功。

每次请求最多10轮ReAct模型调用，另有前置结构化路由；累计最多10次工具调用，整体90秒，每轮还受LLM_TIMEOUT限制。同参数连续重复调用会提前熔断。NOVA模型输出预算4096 token，受LLM_MAX_TOKENS上限约束。后端生成的证据正文不直接采用模型自由文本；默认限制展示条数，更多细节可分项追问。

## 更新和排查

转账任务新增三张表，由后端启动的建表流程创建；保留已有.env和数据库。Docker部署同步源码后更新前后端：

```bash
docker compose up -d --build backend frontend
```

刷新页面。仅前端样式变化可以单独重建frontend；仅后端预算/工具变化可以单独重建backend。修改.env后需重新创建后端以更新注入环境，方式见模型配置文档。3010/8010独立演示环境要更新其实际运行服务，不混用数据库或通过删卷更新页面。

源码开发需要重启后端，在frontend下安装锁定依赖并启动开发服务：

```bash
npm ci
npm run dev
```

| 现象 | 核对方式 |
|---|---|
| 仍显示导航原型、禁用输入或旧遮罩 | 确认实际运行前端构建已更新；本轮工具接入还需要更新后端 |
| “离线规则”不支持复杂提问 | 检查LLM_MODE及有效模型配置，重启/重新创建后端；不显示密钥排查 |
| MODEL_OUTPUT_INCOMPLETE | 模型未完整生成；length提示输出长度限制，其他原因提示中断。检查低于默认4096的自定义LLM_MAX_TOKENS，或分项查询。后端日志保留原因和预算，不保留原始回答 |
| MODEL_TIMEOUT或AGENT_TIMEOUT | 分别为单轮模型时限和整体时限；保留输入后可手动重发，不自动重复请求 |
| AGENT_STEP_LIMIT | 模型未在10轮内结束；明确对象/范围或拆分问题 |
| 选中对象未找到 | 可能未选择、已删除/改期、跨店选择或无权访问；刷新并重新选择，不通过聊天指定其他用户身份 |
| 日历窗口没有安排 | 检查日期/时区或指定其他范围；不代表所有日期都没有活动，也不代表一定空闲 |
| 订单状态与旧页面不同 | 检查当前店铺和查询时间，刷新页面；NOVA读取付款状态而不持久化对账 |

## 聊天理财

可说“推荐债券基金，我自己选”“帮我做理财规划，保留10000元现金”“查看我的理财持仓”“查看010969详情”。目标推荐不计算配置比例；未明确产品时由本人在候选卡选择。规划卡支持现金三金额联动及必要比例减持，表格展示模型建议，下方列实际执行金额。

指定名称、代码或某张卡的候选序号仍须服务端核实。每只申购金额、每只赎回的份额／金额／比例在卡片中核对，整批各一次确认和统一MFA。先赎回后申购时，核实实际到账后创建新的申购方案，不能沿用赎回确认或验证码。刷新／重开会话会读取任务引用与原号结果；未知结果不换号重下。

卡片可暂停后续步骤、恢复核对、放弃未提交草稿或修改完全未提交的方案；不能撤回已成交操作。详情见 [NOVA理财任务接口](../contracts/NOVA理财任务_API_v0.1.md)。夏普排序和历史批量缓存暂缓。


账单查询现在附带指标、分类趋势图、预算进度和分项结果卡。完整依据可展开；刷新恢复查询时快照，点击工作台链接查看最新数据。旧会话仍显示原文字。更新需要同时构建前后端，新增快照表由启动流程创建。详见 [账单查询可视化](../frontend/nova_bill_results_20261027.md)。
