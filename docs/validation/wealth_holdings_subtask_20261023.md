# 持仓主任务与赎回子任务修复（2026-10-23）

用户截图显示：持仓表已勾选两行，聊天“赎回已选持仓”却被引导至另一对话的理财规划。用户明确赎回应为“查看持仓”的可选子任务，也允许一句话串行进入。

原因：持仓复选框只保存在表格本地状态，未像候选选择一样保存当前卡片的可见/已选上下文，也未激活聊天补充焦点。后端未把positions→redeem作为同一任务的接续处理，模型有机会生成另一任务并触发重复检查。

修复：

- 勾选、清空、单只赎回及批量赎回同步当前持仓引用，激活该卡片赎回输入焦点。发送聊天前等待该卡片上下文保存完成，避免刚勾选立即发送的竞态。
- 赎回沿用原task_id，保留持仓来源，标为“我的持仓与赎回”。从服务端勾选引用恢复产品，并重新核对银行当前持仓及版本；不把勾选当作交易授权。
- 数量缺失留在原任务填写，空选提示在原持仓卡勾选；过期/非当前持仓引用拦截，不切换另一对话或放宽重复任务保护。模型将当前赎回误解释为规划时拒绝跳转。
- 串行“先查看持仓→赎回”沿用前项持仓任务，缺选时保留原持仓卡等待选择，成交后才允许下一项。手动确认与MFA不变。

实际验证：SQLite/PostgreSQL卡片和队列回归44 passed / 75.26秒；最终持仓子任务专项10 passed / 22.78秒（有重叠，不累加）；前端102 passed / 0.815秒，TypeScript/Vite生产构建通过。测试覆盖既有其他对话规划不干扰本任务、空选、银行持仓变化、串行复用和不产生订单/占款。本轮未以本人账户做确认、MFA或金融交易，未声明真实模型所有措辞已验收。
