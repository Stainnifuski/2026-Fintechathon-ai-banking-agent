# 类别搜索与换批的行情等待定位

2026-10-18，多伦多，本地main 766a179-dirty。未切换数据库，未提交或推送。

## 原因与处理

正式服务观测到一次`/wealth/actions`耗时9037.5ms，其中`/internal/bank/wealth/catalog`耗时8061.7ms；该阶段按代码刷新新展示的3只基金净值。换批会展示未缓存代码，因此每批可能重新等8秒行情截止。另有前置资产范围读取可能刷新持仓净值。瓶颈不是806只离线资料加载或大模型调用。

类别、名称搜索和换批现通过专用浏览读取适配器：只读取本地已安装产品资料、已有净值及当前账户/评估/资格/范围。覆盖公开`/portfolio/recommendations`和页面`/actions`中的`recommend_products`前置读取及最终候选卡片资格复核；不停用风险、停售、上下文或资金范围校验，不将旧净值伪称实时行情。

内部资产及目录读取新增可选`refresh_quotes`，默认仍为true；只在浏览路径显式false。其他功能和交易预检保留既有按需行情刷新。线上没有“调用行情即报错”的限制，没有删除行情接口或全局关闭行情；未来少量行情需求可在相关步骤显式使用原接口。隔离测试的观察函数用于证明浏览链没有意外联网，只在测试进程注入。

## 同环境双库观测

同一容器、同一源码、完整806池、同样的独立测试身份/评估与一笔测试持仓，通过ASGI HTTP运行；均无外部行情调用。每类别搜索一次、换批两次：

| 数据库 | 债券搜索 | 债券换批1/2 | 混合搜索 | 混合换批1/2 |
| --- | ---: | ---: | ---: | ---: |
| SQLite | 1.3559秒 | 1.0339 / 1.0366秒 | 1.1730秒 | 1.2107 / 1.2090秒 |
| PostgreSQL | 1.6898秒 | 0.9344 / 0.9120秒 | 0.9809秒 | 0.9530 / 1.1254秒 |

每次112—121次SQL；累计驱动执行时间SQLite约0.094—0.140秒，PostgreSQL约0.539—0.867秒，均不是原8秒主要等待。当前总响应在约1秒量级，不能根据原联网请求的9秒判断需要切回SQLite。余下开销包括重复的资产、身份、评估、上下文和候选资格读取及Python处理；本次没有为减少次数而跨请求缓存这些动态事实。

该表是少量定向观测，不是并发压测或正式本人账户测速，也不含Nginx和浏览器渲染。原9秒来自正式日志，与本表不是严格A/B；可确认的是原8秒行情依赖已从浏览链移除。
