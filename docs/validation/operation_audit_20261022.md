实现说明：[操作审计](../security/operation_audit.md)。机器可读结果及全量失败清单：[operation_audit_20261022.json](operation_audit_20261022.json)。

## 实现范围

- 240个API入口的精确分类清单与漏接检查。
- 71张业务表的事务级变更审计，21张审计/锁/缓存/资料表另行分类。
- 35个模块、117个明确服务边界的决策/执行观察；HTTP、AI、权限、银行事实、后台任务、任务压缩和清理相互关联。
- 本人操作记录页面：日期/业务/结果/权限/对象筛选、请求链路、对象跨请求生命周期、脱敏JSON导出；商户也有操作记录入口。
- SQLite开启外键约束验证；新增表重复初始化、保存点回滚、存储故障、备用记录与幂等补录验证。

## 专项用例

| 覆盖点 | 验证方式 |
|---|---|
| 请求、状态提交与结果区分 | 真实HTTP请求与数据库变更，待确认不显示成交成功 |
| 私密字段 | 嵌套验证码/密码/手机号被排除，基金代码和金额保留；兼容写入器同样过滤 |
| 用户隔离 | 其他用户的trace、对象、分页游标和导出不可访问；未登录返回401 |
| 游标/导出 | 游标签名绑定身份和筛选，分页不重不漏；导出31天/5000条限制 |
| 历史兼容 | 旧事实只读投影，权限保留delegated，缺失确认和历史链路不伪造 |
| 幂等与未知结果 | 实际银行模拟响应丢失后原号重试，一次扣款、一次提交事实，多次尝试可见 |
| 原子性 | 注入审计写入失败，账户变更回滚；物理审计表缺失返回稳定503错误 |
| 回滚 | 整个事务及保存点回滚后保留拒绝观察，不恢复已回滚的资金状态 |
| 生命周期 | 批量删除DAG节点前留存命令/依赖/版本摘要；聊天任务可关联后续银行事实 |
| SSE | HTTP 200流内工具失败仍保留失败事实，传输状态与业务状态分开 |
| 后台任务 | 实际worker等待本人确认时有归属正确的系统执行记录，不冒充已确认或成功 |
| 恢复日志 | 0700/0600权限、容量边界、故障后原ID补录、重复补录不重复写入 |
| 全部存储失效 | 在进入关键业务前返回AUDIT_UNAVAILABLE，账户不扣款 |
| 覆盖清单 | 实际路由和数据表与登记清单一致；新增未分类入口使测试失败 |

专项统计以机器可读记录中的最新结果为准。PostgreSQL用例保留并跳过：本机没有提供专用 `BANK_TEST_DATABASE_URL`，Docker引擎也未运行，未为验收启动或操作现有银行数据库。

## 业务回归与全量边界

受影响业务专项覆盖转账银行原子性、卡片、短信验证、NOVA普通/流式对话、聊天转账任务、安全熔断及目录升级。该组在测试会话隔离后为 **125通过、29跳过**。

全量离线测试存在既有失败，不能声明全仓库全绿。对照干净HEAD `04874bba682e0c6383152ef21ea80766777219bf`，111个同名失败用例在原始版本同样失败，主要是旧理财测试未建立当前执行要求的资金上下文，以及旧等待计价/撤单、读超时等预期。

另外一个用例 `test_verification_failed_attempts_are_limited_without_storing_code[sqlite]` 在本工作区关闭审计监听器与审计装饰器后仍失败：现有安全锁定规则返回 `SECURITY_LOCKED`，用例期望 `TOTP_INVALID`。未为使旧用例通过而降低安全限制。

全量执行的最终数量、失败节点及分类保存在JSON中；专项通过不能替代未执行的真实PostgreSQL并发验收。测试默认离线，没有调用真实模型或真实短信服务。

## 页面验收

使用独立临时SQLite后端和隔离前端页面，数据标识为验收样例。通过现有浏览器工具实际验证：

1. 加载本人记录并按“转账”筛选。

3. 切换关联操作，展示“创建任务—风险校验—本人确认—银行结果”，移除无关请求步骤。

## 自审修正

- 保留旧账务审计的事务原子性，新增结构化表不改变旧风控计数和动作名。
- 适配FastAPI的普通及惰性包含路由，保留框架自身的依赖清理与流式处理。
- 明确保存点、外层回滚和结果未知的不同含义，不将HTTP成功直接作为银行成功。
- 目录升级的固定账本保护允许合法新增审计；升级/重复升级回归通过。
- 审计对象增加ORM关系以保证开启外键时按正确顺序插入；Core INSERT/ON CONFLICT也留痕。
- 测试专门隔离独立HTTP审计会话：旧用例仅替换业务会话是不够的。早期由U1/U2等测试身份产生的观察段已保留在受限的本机隔离目录，不参与应用恢复；不删除证据、不改动银行余额。
- 备用段先完整写入/fsync再原子发布，未补录/不完整段不覆盖；运行期也自动重试恢复。
- 查询与导出不递归复制审计历史，操作者与归属用户分开展示。
