# 操作审计

2026-10-22：按已确认的[实施方案](../plans/operation_audit_plan_20261022.md)实现。入口为银行工作台侧栏“操作记录”，仅查看本人数据；未新增全库审计员权限。

## 记录内容与来源

- API访问：服务端请求编号、路由模板、耗时、响应/连接状态。流式HTTP 200与业务结果分别记录，断开不视为交易取消。
- AI：结构化路由/意图、目标依赖、受控工具集合、工具参数摘要、校验/阻断、结果和答案证据引用。保留模式及已有模型证据信息，不复制提示词、原始回答、整段对话或内部推理文本。
- 授权：转账累计风险依据、卡片方向型风险、理财适当性、确认、MFA及拒绝。各模块记录亲自验证的事实。
- 业务状态：转账/定时/收付款退款、理财、卡片订阅、商店、账单规则/预算/商户、联系人、日历、身份和会话等已登记表的增删改；包括ORM和受控Core批量写入。
- 后台：到期转账、理财任务推进、任务压缩/关闭/清理。空轮询不单独生成业务完成事实。

审计表为 `audit_events` 和 `audit_event_objects`。旧 `audit_logs` 及转账状态事件继续使用原字段与动作名；新事实在同一业务事务内适配到统一事件。旧记录通过只读投影显示并标记资料不足，不补造历史意图、确认或验证。来源引用避免同一旧事实重复显示。

一次请求/后台执行有独立trace，内部银行调用在校验内部凭据后接受父trace；后续确认、验证和重试使用稳定的任务、操作、计划和授权对象聚合。外部trace头不授予身份或权限。人工操作者和数据归属分别保存。

## 事务与故障

关键状态变更及审计在同一数据库事务提交。审计写入失败则对应未提交变更回滚，API返回 `AUDIT_UNAVAILABLE`。已提交的银行结果不因访问收尾日志失败而改写；响应丢失记录为未知，继续沿用现有原操作号核对机制。

观察事实（如风险判定或被拒绝的尝试）可在外层事务/保存点回滚后独立保存；已回滚的资金或状态变化不会被重放成已提交。独立写入在原事务结束、释放锁后进行，避免SQLite自锁。任务压缩前的节点与命令摘要随删除事务留存；演示归档清理保留旧审计。

审计事件采用应用层追加写入保护。数据库管理员直接改库的防篡改、外部不可变归档及法规保存期限不在本次新增范围。

进程在两个持久化边界之间退出时，只显示已留存阶段；没有终态证据的请求保持未完成，银行操作继续按原号核对。审计不声称能够恢复尚未提交的模型内存内容。

## 备用记录与恢复

普通访问与失败观察在数据库不可写时可进入受限的本地追加日志。关键账务的事务审计不能用文件替代。数据库和备用存储同时不可用时，新请求在进入业务前返回503；已经提交的结果保持真实状态。

配置：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `AUDIT_FALLBACK_DIR` | `var/audit-recovery` | 专用恢复目录，权限0700，文件0600 |
| `AUDIT_FALLBACK_MAX_BYTES` | `67108864` | 未补录文件总容量，达到上限不能覆盖旧文件 |

Docker将恢复目录挂载到独立的 `audit_recovery` 持久卷。单事件上限256KiB；写入、fsync完成后才原子发布待补录段。进程间锁保护追加/补录；不完整段保留并报告降级，不覆盖或删除。

数据库初始化后及运行期间每30秒尝试补录，按原事件ID去重，原发生时间保留，记录时间反映补录时间。只有数据库事务提交后才删除完整待补录段。`/health` 的 `audit` 字段、API `X-Audit-Status` 和操作记录页显示降级状态。`X-Request-ID` 用于查找本次请求。

## 隐私与查询

字段逐层白名单过滤；仅保留必要金额、币种、产品、版本、规则、状态和证据引用。密码、Token、API密钥、完整手机号/卡号、TOTP密钥/二维码、验证码、原始问卷答案、备注/日历正文不进入新审计。数值验证码与错误码分开处理，基金六位代码不会被误删。审计查询结果不递归复制为新审计内容。

本人查询、对象关联、trace、分页和导出均受服务端身份隔离；分页游标签名并绑定本人和原过滤条件。默认界面显示业务步骤，可选择展示请求与连接步骤。历史无法确定的操作者/权限/链路不推测。

接口：

| 接口 | 用途 |
|---|---|
| `GET /api/v1/audit/events` | 日期、业务、动作、结果、权限、对象筛选，游标分页，每页最多200条 |
| `GET /api/v1/audit/traces/{trace_id}` | 单次请求与子步骤，可继续分页 |
| `GET /api/v1/audit/objects/{type}/{id}?domain=...` | 关联对象跨请求生命周期，跟随本人任务/操作/授权关系，最多展示500条并明确截断 |
| `GET /api/v1/audit/export?since=...&until=...` | 与列表相同筛选，最多31天、5000条的脱敏JSON导出 |

查询响应不缓存。审计查看/导出自身也留痕。无普通更新或删除审计API。

## 维护与验证

完整API分类清单为 [operation_audit_routes.json](../contracts/operation_audit_routes.json)。专项测试对实际路由清单和数据表分类做精确检查；新增入口必须同时更新审计分类与覆盖证据。

新增表和索引由现有 `Base.metadata.create_all` 增量创建，不改旧表/旧账本结构，可重复执行。目录升级保护允许合法追加审计，原有账户和队友模块保护继续保留。测试只使用临时数据库；PostgreSQL需显式提供以 `bank_test_` 开头的专用数据库。
