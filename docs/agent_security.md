# Agent 安全边界与运维

本次加固覆盖应用端的提示词注入、知识库篡改、业务 Skill 篡改和异常模型输出。它不是“模型已无后门”的证明。检测规则只是辅助信号；授权、归属、参数引用、限额、本人确认和 MFA 仍由银行服务独立执行。

| 边界 | 本次补充 |
| --- | --- |
| 用户与历史 | Unicode 格式字符规避与角色伪造检测；历史仅保留 user/assistant 正文，隔离明显恶意历史；页面与引用在任务处理前检查 |
| 模型输入 | 所有文本、结构化和工具请求统一加入信任边界说明；工具结果含明显覆盖指令时不外发；上下文上限 1 MiB |
| 模型输出 | 拒绝重复 JSON 键、非有限数字、非对象和超过 64 KiB 的工具参数；普通及流式响应上限 512 KiB，超限停止 |
| 知识资料 | HMAC-SHA256 绑定文档 ID、完整正文和全部元数据；密钥在数据库外；未签名、错误签名或含明显注入的资料不参与检索 |
| 业务 Skill | 8 个 Skill 的发布校验清单；加载与启动时校验，文件缺失、改写、符号链接或清单不匹配时拒绝；构建与启动不自动批准新哈希 |
| 模型供应端 | 远端必须 HTTPS，本机回环可 HTTP；可配置精确来源白名单；关闭重定向和隐式环境代理；ASR 只接受代码中审核过的权重提交 |
| 身份与秘密 | 移除公开默认 JWT 密钥及相关默认密钥回退；拒绝短密钥和已知占位符；缺省生成独立且跨进程、重启持久的随机登录密钥 |
| 审计 | 拒绝写稳定事件码，不写攻击正文、客户名称、秘密或 URL；单次检索合并资料校验拒绝事件 |

原有工具白名单、Pydantic Schema、参数引用与归属核验、交易确认、MFA、有限调用预算和事实输出核验仍保留。模型文字不能授权交易。

## 密钥与旧资料

- **原有强 JWT_SECRET 必须保留。** 新部署设置至少 32 字节的强随机值，或留空使用私有文件。更换密钥会使旧令牌失效，也可能影响历史会话、卡号推导和短信挑战。原来使用公开默认密钥或空密钥的账本须先备份并单独迁移；不要恢复公开默认密钥。
- `AGENT_KNOWLEDGE_SIGNING_KEY` 是独立的至少 32 字节随机秘密。留空时在 `AGENT_SECURITY_DIR` 下生成 `knowledge-signing.key`；登录缺省密钥为同目录的 `jwt-signing.key`，两者独立。
- 默认目录为项目 `var/agent-security`，容器中为 `/app/var/agent-security`。Compose 已新增 `agent_security` 持久卷。不得删除、提交或公开密钥目录；备份按秘密管理。文件按 0600 创建，拒绝符号链接和宽松文件权限。多实例需共享相同部署秘密或受控密钥卷。
- 丢失、轮换密钥或签名不符时，不会退回仅比较哈希。旧资料须从可信发布材料或审核后的原导入过程重新签名。
- `seed` 仅对与重新构造的批准资料一致的旧行补签，不覆盖或批准被改写的旧行。模拟资料初始化从发布文件及哈希清单重建，不使用可写数据库的产品行作为补签依据。混合资料需由管理员重新执行原审核导入流程，不能按数据库当前内容批量签名。
- 未补签的旧资料会减少可检索结果，不触发模型猜测或绕过交易校验。代码内置的当前项目说明不依赖数据库行。
- 可设置 `LLM_ALLOWED_ORIGINS=https://api.deepseek.com`，多个来源用逗号分隔；匹配完整 scheme、主机与显式端口。未设置时仍仅使用服务端配置地址，但不限制 HTTPS 服务商名单。需要代理的部署应另行审核显式连接配置。

## 校验与维护

只读检查 Skill 清单：

```bash
python -m backend.app.security.release_integrity
```

主动修改 Skill 后，先审查差异，再明确更新并一起评审发布清单。禁止将更新命令放入构建或启动脚本：

```bash
python -m backend.app.security.release_integrity --write
```

攻击回归不请求真实模型、不下载权重、不连接真实账本：

```bash
python -m pytest tests/security/test_agent_trust_boundaries.py tests/security/test_knowledge_and_skill_integrity.py -q
```

扩展 NOVA 接口回归需要设置测试专用 `INTERNAL_BANK_TOKEN`，不要使用开发者的真实凭据。PostgreSQL 并发验收需独立 `bank_test_*` 数据库。

## 已知范围与限制

- 签名证明“经批准的导入后未被篡改”，不能证明外部资料真实。审核前已投毒的合法来源、语义隐蔽的注入、有效旧资料重放及提供商内部训练后门仍需来源审核、版本撤销和独立红队评测。签名不是事实正确或交易授权证明。
- Skill 清单和应用代码是发布信任根。攻击者若能同时改写代码与清单，或窃取签名密钥，此机制不能抵御；需由部署系统提供只读镜像、发布审批与访问控制。
- 文本 LLM 通过外部接口使用，未包含训练/微调流水线；本地无法认证其训练数据或排除权重后门。ASR 固定提交与 `trust_remote_code=False` 限制替换及远程代码执行，不证明批准权重没有行为后门。
- 本次未认证全部第三方依赖。后端仍有范围版本依赖；发布前应在目标 Python/平台生成并评审完整含哈希锁文件、扫描漏洞并固定镜像摘要。开发机安装列表不能充当可复现部署锁文件。
- 项目仍是模拟银行。现有本地短信收件箱、模拟交易和本地测试限次开关保持原有含义，不能作为真实银行上线验收。
