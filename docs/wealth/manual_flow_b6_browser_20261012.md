依据 02 v0.3 的 B6、第5.2—5.4节。本轮使用真实前端组件和公开 HTTP 交易接口，在全新隔离 SQLite 中完成操作；不是录制按钮成功响应。

## 环境与隔离

- 普通演示仍为 3000/8000，本轮未往其账户添加订单。
- 浏览器验收为 `http://127.0.0.1:3011/?wealth-dev=1`，专用后端绑定 127.0.0.1:8011。
- `tests/browser/wealth_b6_server.py` 只接受仓库 `.tmp` 下全新的 `browser_bank.db`；不删除或重置已有库。不使用普通 main 启动种子/后台 worker。
- A 部分注入同契约七产品固定方案；银行、JWT 身份、本人确认、绑定短信校验及结算保留真实实现。LLM_MODE=offline；未读取 `.env` 或使用真实模型。
- 仅专用开发前端设置 VITE_B6_BROWSER_TEST=true，显示“B6 隔离验收”说明。生产构建及普通演示没有此标记，也未新增正式导航。
- 隔离账户预设风险评估作为测试夹具。这里不声称验证了真实用户亲自答题；该行为仍沿用原评估入口及分项验收。
- 人工推进测试业务时钟由脚本的 `/api/v1/b6-test/advance` 完成；该路由仅存在于这份独立脚本，不注册普通后端、NOVA 或生产启动入口。虚拟业务日期与现实时间分开。

账单的定量排除不能仅用“页面0笔”证明：测试时钟已推进到现实日期之后，页面报告还受现实账期截止影响。因此排除规则的完整统计/明细/文本及真实流水数量仍以 B6 第一轮和 bill_boundary 隔离回归为证据；本轮验证页面说明和原流水入口。

## 启动方式

在仓库根目录、两个分别配置环境的终端中运行；下面是开发验收脚本，不能替换普通启动方式：

```powershell
$env:B6_BROWSER_DATABASE = "$PWD/.tmp/b6-browser-<全新目录>/browser_bank.db"
.venv/Scripts/python.exe tests/browser/wealth_b6_server.py
```

前端终端：

```powershell
$env:BANK_API_BASE_URL = 'http://127.0.0.1:8011'
$env:VITE_B6_BROWSER_TEST = 'true'
Set-Location frontend
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 3011 --strictPort
```

隔离演示登录使用页面显示的虚构演示凭据。当前保留页面已经完成交易，可继续查询订单、持仓和收益；重新从初始固定方案跑完整链路需全新隔离环境，不能把旧固定方案冒充更新后的模型输出。
