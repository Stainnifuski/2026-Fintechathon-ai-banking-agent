# 聊天、工作台与人工接管的名称搜索

新对话指名投资或购买某个名称、简称、名称片段或代码时，NOVA 使用 `plan_wealth(kind=recommend)` 的 `name_query` 和本轮原文引用进入目标产品推荐。搜索词由模型作结构化语义抽取，服务端逐词核验引用，不用关键词规则解析用户话语，也不补全或猜测某只产品。

聊天卡片和操作台“产品名称或代码”统一调用 `recommend_products` 的 `filter.mode=name`，底层共享 `ProductIndex.match`。名称采用包含匹配；空格分隔的多关键词须全部出现在产品名称中，统一大小写和全半角。产品代码按完整代码匹配，不将代码前缀自动解析成某只产品，也不承诺纠正错别字或匹配任意别名。

名称搜索只产生候选条件。多个、一个或零个结果均不会自动选定产品；候选继续使用现有账户范围、正式风险评估、产品资格与版本核验。无匹配保留搜索条件供修改，成交仍需用户选择、金额核对及本人确认/验证。尚未完成评估时，名称条件保留在原任务卡中。

操作台的检索词与候选、选择一起保存在按用户及账户范围隔离的草稿中。卡片视图保存当前检索方式、词、类别及对应请求号；恢复时只使用当前请求的视图，避免旧检索覆盖新指令。人工接管沿用同一张卡和同一搜索入口，保存检索与本人已选状态，后续操作仍须重新核验银行事实。
