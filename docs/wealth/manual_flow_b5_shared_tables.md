## 本轮变化

- StructuredActionPanel 直接复用 OrderTable、PositionTable；删除简化混合表。订单/持仓查询结果分别放在自己的按钮下方，同时保留。
- 两套完整列、独立详情状态、每页行数、页码和勾选。全选仅当前页；跨页选择保留；重新查询不覆盖另一表。共享草稿保存两套独立状态，退出或资金范围变化清空。

- 持仓逐行/多选赎回选定具体持仓并定位到输入表单，不套用旧输入；份额、市值、比例及既有本人确认/验证码保持不变。
- 整体/单产品收益入口复用 ReturnsView，包含日/月/年/累计、日期、月日历、序列表、完整性与产品贡献。统一入口查询按钮的粒度/日期作为初始条件传入。
- 受理、撤单等操作触发账户回读后，已经打开的双表同步更新完整银行事实；删除失效引用并收缩越界页码，不等结算才更新。

## 动作响应补充（兼容已有字段）

`list_orders` / `list_positions` 的 data 保留原有 rows/page/page_size/pages/total；增加：

```text
table_data: {object_type: orders | positions, scope_key: asset_scope_id, rows: 全量授权行}
snapshot_id: AssetSummary 的 snapshot_id
```

完整表格在同一份全量授权快照上做前端分页，不多次分页抓取后拼凑不同快照。table_data 没有扩大授权范围；服务端仍在读取当前银行事实、验证主体/context/选择后生成。客户端核对类型和 scope，工作台状态 key 另绑定本人及 context。原分页接口消费保持兼容。选择、授权证据及会话版本没有放入这些返回字段。
