# 当前理财工作台与临时状态（2026-10-04）

本轮覆盖旧文档关于长期理财聊天存档、主任务列表和刷新恢复的要求。保留原产品、价格、银行申赎/快赎、适当性、确认授权和账务规则。

## 使用（以用户本轮范围修正为准）

银行事实 → 唯一当前方案 → 聊天与必要任务进度 → 持仓表。去掉旧轮次对话、保存方案列表、主任务选择、配置调试表单、外部资产诊断/目标差额、重复方案、需求编辑表和金额编辑表单。产品、分配金额、简短理由和既有走势图弹窗保留。

已有有效风险评估时，仅说投资金额即可推荐，不补问期限、目标、具体用途或保留现金。未评估进入原问卷，本人确认结果后继续本次需求。未提供的语义字段保留未提供，365天仅为透明的内部筛选窗口，不伪造用户回答。规则按风险、费用、流动性筛选，尽量全额分配投资金额；仍保留原60%家族/单产品集中度、最低/最高金额及支付能力保护。确实无法全额分配时注明实际金额和规则原因，不拆出一份默认现金配置。

提交前自然语言修改金额，更新同一个方案版本并作废旧预览，再确认新金额。已提交/结果未知交易不覆盖，说明原请求已提交并询问是否另外投资；明确另投后建立新方案、新操作号和新授权。自然语言仍使用严格 `wealth-semantics-v1`，不增加固定句子关键词匹配。

“一键申购全部”打开统一预览，一次本人确认加模拟授权；银行明确受理全部申请后提示“申购成功（申请已受理）”，在持仓表展示待确认份额。真实失败/结果未知不报成功，在途不能当作可赎持仓。旧单产品申购/逐笔采用/对比/订单与撤单页面去掉，已有后端能力保留。

持仓表选择产品、份额及普通赎回/快赎，再确认授权。独立持仓赎回复用既有单笔子DAG、预览及银行写入校验；不由 DeepSeek 生成赎回订单，不重写引擎，不增加核对模块或测试时钟。普通赎回展示占份额和等待计价/到账，快赎成功同事务到账。

刷新、退出重进、登出/切换用户和新对话从空白开始；余额/订单轮询、走势图弹窗和问卷续接不清空当前会话。仅移除旧 `wealth-message-{userId}` 存储键，不删其他模块或管理员工具存储。关闭不是撤单或重置资金。

## 窗口接口

均为本人 JWT、`/api/v1/wealth` 前缀：

| 接口 | 用途 |
|---|---|
| POST /sessions | 新窗口，关闭本人的前一个窗口并回收临时内容 |
| GET /sessions/{sid} | 显式当前窗口读取；关闭后404；网页不用于历史恢复 |
| POST /sessions/{sid}/close | 可重复关闭，作废未提交授权，删除文本及草稿 |
| POST /sessions/{sid}/preview-link | 关联持仓赎回预览及单笔子DAG，关闭时作废未提交授权 |
| POST /sessions/{sid}/continue | task_id；明确续接本人同上下文未完成任务，只读事实，不授权 |

旧 `messages/history` 返回 null，`messages/archives` 返回空 items，仅为兼容保留。现有方案/子任务接口继续供集成使用，不提供网页长期方案列表。二号应保存银行操作号与最小回执，不依赖聊天/历史卡片。

## 执行生命周期

单笔银行受理已明确后删除无用 Agent 节点；Agent COMPLETED/BANK_ORDER_QUERY 表示交接银行，**不表示银行已结算**。银行订单、占款、批次、到账流水、授权审计和幂等结果保留，继续原号查询、撤单或结算。

复杂任务保留最小身份、依赖、命令、银行操作号及控制状态。窗口关闭后后续买入停止自动推进；用户明确续接，到账后读取现金，生成新预览并再次确认授权。结果 UNKNOWN 保留，按原号查询，查不到也不重新提交。完成/取消且无未决银行节点时删节点和文本，Task/控制回执只保留最小关联。

现有 worker 回收无活动24小时会话文本、草稿和旧消息请求；不依此删除订单或未完成依赖。新窗口初始化重试旧窗口关闭，不依赖浏览器关闭通知。模型处理期间关闭窗口会拒绝迟到响应。

## 管理员清理

先停止银行/Agent写入，确认实际 DATABASE_URL，再预览：

```bash
python -m scripts.clean_wealth_workspace
python -m scripts.clean_wealth_workspace --apply --backup-dir /demo/backups
```

SQLite apply 自动在线备份并 integrity_check、记录备份 SHA。源库名限制为已采用演示库 `wealth-demo.db` 或 `banking_agent.db`，不可替换成随意路径。PostgreSQL 先独立 pg_dump，再通过 `--backup /path/verified.dump` 提供备份。脚本不清空整个数据库。

清理物理删除理财 Conversation/Plan/ChatRequest，剥离多余 Agent 节点和执行状态；包含普通及模拟账户的理财记录。确认归属的专用表处理，共享转账/店铺表不删除。清理前后对账户、流水、订单、批次、占款、结算、产品/NAV、风险评估、目录缓存、转账、店铺、订阅、卡片和日历等保护表记录数及完整字段 SHA256 比较；不同立即报错，停写调查并使用已核对备份恢复。重复执行应稳定。

本地备份/明细日志在数据库卷或忽略的 `.deps`，不提交密钥、账本或原对话。无需新表或 schema 版本迁移；已有表结构保留以兼容当前窗口/子任务接口。部署旧库需显式执行清理，启动不自动全库清档案。
