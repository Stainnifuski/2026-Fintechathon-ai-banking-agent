# 理财规划知识库解释与进入确认

知识库文件：`backend/app/knowledge/wealth_planning.md`。内容原样来自用户提供的《理财规划_简明知识库.md》，包含作用、三板块、理论采用边界、配置计算方法和常见追问。引用文献链接作为来源记录，不自动打开或抓取。

NOVA 在已有语义路由调用中输出 `planning_mode`：已有具体业务保持原路由；未被其他功能覆盖的宽泛投资意图先解释并邀请；模型问答只解释；明确要求或确认开始规划才允许新建卡片。启动引用必须逐字来自当前用户消息。未确认的需求不先打开风险问卷、规划卡或任务图。

DeepSeek 接收完整知识库、当前问题、最近对话、阶段及系统提供的已授权本地资料，生成简短自然的回复正文，并单独返回支撑每段事实的来源引用。可以在合适时沿用知识库原句，但服务端不再摘录、拼接知识库段落作为正文。来源引用仅供内部核验，不显示在正文中；无效依据对应的回复段落丢弃，未覆盖内容如实说明。该解释路径不暴露业务工具或外部搜索工具，也不依据模型记忆补充外部理论或事实。纯解释不会修改已有任务卡。

邀请中的“一键进入理财规划”作为本地动作按钮显示，点击后在当前会话发送明确的启动请求，不跳转网站。邀请保存在正常对话文本中，历史恢复后仍可用；自然语言确认也通过相同的结构化语义判断进入。按钮在请求处理中禁用。

首次介绍通常为100至160字的一个短段：连贯概述心理账户等研究依据、整体协调思路、凸优化及持仓约束投影、个人输入与三板块配置，再用通俗语言点明资金安排的用途，不逐项展开原理，也不提供固定回答模板。相关诺奖信息严格沿用知识库的身份、研究贡献及采用边界，不将数学方法归为塞勒的理论。确认启动后若此前已介绍，不再重复泛泛解释，按实际卡片状态承接下一步；追问则只针对对应原理生成回答，不强行带上其他人物或理论。只有问题涉及风险、收益保证或采用边界时才说明相应限制，避免每轮堆砌风险提示。风险评估、候选选择、本人确认和 MFA 等原有规则保持；聊天中的进入确认只允许创建规划任务，不授权交易。原有产品行情获取及其他功能不受解释路径的外部检索限制影响。

开启本人调试记录时，`planning_knowledge_input` 保存实际模型消息、知识内容摘要和阶段，`planning_knowledge_output` 保存模型正文、内部依据及最终可见回复，便于核对传入内容与最终回复路径；诊断沿用现有的加密、按用户隔离的存储。

验证：`tests/unit/test_planning_knowledge.py` 覆盖邀请、追问、确认、未覆盖内容、来源核验、本地资料范围和其他业务；现有 NOVA 路由、任务图及理财卡片测试一并回归。
