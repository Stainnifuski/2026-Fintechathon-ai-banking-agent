## 新的 HTTP 连续链路

使用全新临时 SQLite，原公共 HTTP 路由及真实 JWT：

1. 创建未提交 command 与原授权；U1 申请 handoff，进入 HANDOFF_PENDING。
2. U1 不能冒充操作员领取；接管期间仍可调用 /actions 查询订单，不能重新预览交易。
3. U2 为测试进程中明确配置的操作员，领取前不能读取 context，领取后归属 HUMAN/U2 并可核对。
4. U2 不能执行 U1 的授权，返回 NOT_FOUND；交还后任务 AGENT/PAUSED，失去核对权限。
5. U1 使用旧授权执行被 AUTHORIZATION_EXPIRED 拒绝；继续任务后旧授权仍无效。
6. U1 重新预览产生新操作号但保留原金额和产品，状态 AWAITING_CONFIRMATION；不经本人确认/MFA 不能执行。最终订单及现金占用数量均零。
7. wealth_model.understand/explain 和 wealth_dialogue.message 均设为调用即失败，验证此恢复链路不调用新 NLP/模型。

测试开发时修正了两处测试假设：查询订单应走实际 /actions 而非不存在的 GET /orders 集合路由；过期授权的公开执行响应是银行边界 409 AUTHORIZATION_EXPIRED。没有为使断言通过修改业务拒绝逻辑。最终重跑结果见后续记录。
