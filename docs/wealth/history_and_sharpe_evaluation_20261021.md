# 产品历史与夏普：轻量联网评估及暂缓决策

2026-10-21。只做一次有界研究，不安装生产缓存、不启动全池采集或日更任务、不改变推荐排序。用户要求图表优先；夏普优化等理财 Agent 接入后再实施。接口口径以本机AKShare 1.19.1实际源码和[官方公募基金文档](https://akshare.akfamily.xyz/data/fund/fund_public.html)核对，不把“一次Python调用”一概当成“一次HTTP请求”。

## 当前详情为何要等

`wealth_product_detail.detail` 对缺少持久化历史的真实基金，打开时按具体代码调用 `fund_open_fund_info_em(symbol, indicator='单位净值走势')`。**一次返回该基金全段历史**，不是每天逐个请求；本地再筛一年并一次生成1月／3月／1年三个窗口。当前每次重开仍可重新联网，独立进程启动、导入、下载与解析都在等待路径上。切窗口本身复用本次结果。

单基金历史接口没有多基金参数，也没有对单位净值走势生效的日期范围参数。`period`只影响累计收益率走势，不能据此声称单位净值历史只下载最近一年。大多数等待是外部读取与初始化，不是前端画242个点。

### 批量覆盖与约束

`fund_open_fund_daily_em()`实际一次HTTP请求返回最新／前一交易日两期净值，不能回填一年历史。两期至少有一个有效值的覆盖率为804/806（99.75%）：债券241/242、混合500/501、权益63/63。无有效值的是011619（鹏扬淳兴三个月定期开放债券A）和012269（浙商智多享稳健混合发起式C）。这不是“804只当日一定更新”的证明，正式适配还应分别校验每行日期与有效值，缺失按代码补查，不能用0或当天日期填充。

轻量解析仅验证了同来源响应中的datas/showday两数组，未作为生产适配器安装；后续需要字段结构、代码唯一性、有效NAV、日期可见性、历史不可变、官方接口变更及超时的测试后才接入。它有希望去掉本次约15秒的通用JS文本解析成本。

## 是否采用登录后10秒更新

可以将**已预热且只差正常一至两个披露交易日的增量**以10秒为目标；不能把首次建库、停机多日的缺口补采、源站故障或单产品披露延迟都算入保证。最新两期批量响应不足以补三天以上缺口，届时仍需针对缺口代码读取历史。

基础数据可以由开发时先构建，避免用户第一次等全池；建议在现有PostgreSQL使用独立的行情历史表和索引，不必另建账户数据库。按代码／日期去重，保留一年所需观察点及必要窗口基准点。**仅清理这张可再生的图表缓存**，不删除成交、成本批次、审计或交易定价所需NAV。固定806产品规则包与运行行情保持分别管理；预热资料留本机，不擅自把全池实时历史提交Git。

日常应是全应用共享的单个更新任务，登录只检查任务状态，不能每位用户各启动806请求。按中国交易日、已取得日期和披露时点判断是否需要请求；工作日白天已有上一交易日资料则不重复更新。披露后小批更新与次日复核，休市日不虚构新点。失败保留最后可靠值／日期并后台重试，详情优先读本地，不等待全量完成。

后台任务应在独立worker或进程中下载／解析，使用有限并发及短批量入库，前台只读已提交快照；不在Web事件循环同步跑AKShare解析、不持有跨网络等待的数据库事务。这样可以与查询、聊天及交易并行。网络带宽、CPU和数据库仍共享，不能声称零影响；正式实施前需压测同时操作的响应分位及任务延迟，超时／限流主动降并发。此次研究没有进行前台并发负载验收。

**建议顺序：先完成Agent，随后实施历史预热＋轻量批量增量。** 当前详情启动优化留作待定，没有为研究结果直接改变运行获取逻辑。

## 夏普：记录后暂不实施

官方 `fund_individual_analysis_xq` 一次只接受一只基金代码，一次响应包含该基金近1年／3年／5年的可用指标；当前实现未发现多代码批量参数。最新净值批量响应不含夏普，不能从中“直接读出夏普”。多并发是多次HTTP并行，不是一次多基金请求。

4—8个轻量HTTP并发通常首先受源站响应／限流影响，不需要GPU。若每个请求都另起完整AKShare进程，会增加CPU和内存开销；未来独立worker采用复用进程和轻量连接池，先4并发、观察后最多8，并保留超时、退避和失败重试。后台每天批量更新本地夏普，推荐只查本地已完成快照，不能让每次推荐都重新等806请求。

允许使用前一交易日资料，确实提供了日内重试和次日复核余量，但有一项不能忽略：本次20只分析响应都没有明确的指标截至日字段。**今天抓到“近1年夏普”不能证明其已算至昨天。** 后续若采用源站指标，应展示近1年与抓取时点、源截至日未知，不冒称T-1保证；若要严格可验的T-1，则需用已核实至T-1的适当收益序列、统一无风险利率和年化口径自行计算，分红／复权口径也须确定，不能冒充源站官方夏普。这是Agent完成后再决定的两种方案。

20只样本本次均有近1年值，不代表806只都具备近1年值；原806池的保留标准是任一1/3/5年数值可用。不能为了未来只用一年排序又擅自删除缺少一年值的产品。

真实债券／混合／权益类别未来可在类别匹配与资格检查后按近一年夏普决定候选顺序及换批顺序；模拟银行理财／快赎类别保持自身规则，不与真实基金夏普混排。名称／代码明确匹配时以身份和相关性为主，不用夏普把用户指定产品挤掉；LLM负责理解描述与消歧，实际匹配和资格仍由服务端资料核验。当前结构化名称查询是名称包含／代码精确匹配，不能把它误称为已完成NOVA自然语言接线。
