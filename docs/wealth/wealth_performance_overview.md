# 整体理财表现与精简入口

2026-10-23 本地实现，覆盖旧页面“单产品收益／日历／任意日期”交互；底层历史接口继续兼容，不删除金融事实。

## 正式页面

整体理财收益只保留昨日、近一月、近一年、累计四个选项，自动查询全部授权理财产品，包含已清仓的已实现收益。只展示区间收益金额、区间收益率及一条个人收益率曲线。没有单产品收益、日期输入、日历或贡献表。近月／近年从北京时间当前日期向前推一个月／一年，截至昨日；实际展示从首次可核实成交起的覆盖日期。累计也截至昨日。投资本金及闲置账户现金增减不算利润。

曲线复用产品详情图表交互，但数据是个人表现，不是基金净值涨跌。缺失日期保留null、折线断开；少于两个有效点不画线。没有投入可定义的收益率显示“—”，缺资料显示待更新。昨日固定北京时间自然日，不跳过零收益日。非交易日经核实无变动显示0；缺净值不是0，非交易日存在真实收益／费用变化时照实计算。

持仓表仅显示勾选、产品名称、当前金额、昨日收益、剩余持仓收益／率和原详情／赎回操作。份额、锁定、批次、成本仍保存在数据库及详情，不在主表堆叠。持仓收益率=剩余持仓浮动收益/剩余成本，独立于整体区间收益率。昨日收益按账户和产品版本分别核实，跨午夜刷新使用北京时间业务日期。

独立产品资料与赎回区块移除。候选／已选／持仓提供详情；选品提供可选2—4只对比；持仓提供单只及批量赎回。候选卡移除排名说明及资料日期／来源块，来源保留在详情，风险与费用仍可见。

## 计算与数据

沿用订单、成交事件、持仓批次、净值表，不新建收益账本，不复制余额。新普通即时赎回在每批成交记录中写入units_scaled和units。旧记录只读恢复：依据实际订单总份额、明确记录的批次顺序及回放的批次余额分配，并验证精确成本；证据不足或冲突仍为未知，不改写历史事件。事件按有效业务时点、UTC受理顺序排序，同单定价先于到账；SQLite已定义UTC的受理字段按UTC解释，成交来源时区仍必须明确。

区间收益=P期末估值−P期初估值−期间净投入，其中净投入=实际申购支出−实际赎回到账。估值包含尚未到账应收，到账不重复贡献利润。整体收益率采用非年化Modified Dietz：收益除以“期初估值＋按剩余区间时长加权的净投入”。加权使用真实业务时间。非正分母不构造收益率。此法是现金流校正的区间估计，不是年化、TWR或简单收益除以当前余额。

历史估值只能使用查询时已公布、净值日期不晚于估值日的记录；允许晚披露后核实昨日数据，不借未来净值插值。回放快照使用每请求有界缓存，查询仍只读、同一银行快照，沿用净值版本／日期唯一索引及成交operation_id索引。没有新增可变余额副本或破坏性数据库迁移。

## API与Agent

`GET /api/v1/wealth/returns?scope=all&period=day|month|year|cumulative&overview=true`。overview模式拒绝单产品和anchor_date，返回原兼容结果及强类型performance。period=day仅在overview模式表示昨日；旧历史接口原语义保留。

Agent收益工具先取得同一银行整体表现，再生成金额／收益率短答和卡片，查询结果不是交易授权。只读收益、持仓、详情、比较不弹出风险问卷。详情／对比引用原选品任务，生成带parent_task_id的查看子卡，保留原选择／金额／任务焦点，提供返回入口。没有选定对象则澄清，不把全池对比当作独立选品入口。

持仓→赎回仍沿用同一任务；直接赎回同样使用持仓流程。持久队列中收益查询必须有实际银行读取结果才能完成，详情／对比必须明确对象；金融操作仍以银行终态解锁下一项，不能把查看或预览当作成交。YELLOW手动确认、RED本人同意及MFA、两阶段独立MFA及到账屏障保持。
