# 账单数据基础 v3（2026-10-19）

在 v1 报告、v2 消费追溯／订阅／现金流的基础上增加独立辅助数据。原始交易金额、类型、备注和余额不因标签、别名、归并或周期偏好而改变。所有接口位于 `/api/v1/bills`，用户身份只来自 JWT，不接受 `user_id` 参数。

## 功能与口径

| 数据 | 实现及使用位置 | 证据不足时 |
| --- | --- | --- |
| 商户标识 | 当前用户的稳定 `merchant_id`、名称别名、银行商户身份；消费变化、疑似重复和订阅核对使用标识 | 无银行证据时只规范化名称；不同名称需在页面明确归并，不能将不同已核实银行身份归并 |
| 退款关联 | 商户全额退款事实→原付款绑定→成功银行操作→同账户原消费；原单与退款双向查看 | 不按姓名／相近金额猜测；未关联退款独立列示 |
| 本人互转 | 银行操作的出账流水、精确入账流水形成唯一配对；新转账在记账事务中传入已知两笔 ID | 历史时间、账户、金额相同但有多笔候选时保持未配对 |
| 用户标签 | 每笔最多10个，每个1–24字符，规范化后不得重复；可增删、按标签筛选报告及明细，NOVA继承筛选 | 所有标签及绑定限定本人账户；发生实际变更的过期编辑版本返回409；相同结果的重复提交返回当前状态 |
| 周期记录 | 保存月度订阅计划、稳定工资收入及消费支出候选，包含历史观察流水、状态、版本和预测偏好 | 连续至少3个月、每月1笔、日期差≤3天或均为月末、金额跨度≤中位数20%；不满足则不生成／标记失效 |

已关联退款按**到账账期**归入原消费类别：分类 `amount_fen`、趋势、变化归因继续展示消费原额；新增分类 `refund_fen`、`net_amount_fen=amount_fen-refund_fen`。汇总新增 `linked_refund_fen` 和 `unlinked_refund_fen`；`net_consumption_fen` 仍为消费原额减全部到账退款。分类净额之和减未关联退款可与净消费对齐；退款跨期不改写原账期。类别过滤包含该类别已关联退款。

全部账户报告排除明确配对的本人互转，也兼容通过本人的账户ID确认收付款方向的旧流水；单账户报告保留转入／转出。配对缺失与转账是否属于本人账户是两个不同事实。

银行订阅按现有计划推演，取消仍需原有本人确认流程。持久化的工资模式默认纳入估计；识别支出候选默认关闭，须用户手动启用。启用的周期支出从可变消费历史基线移除，避免重复计算；消费削减情景只作用于可变消费。当前月已有观察记录时不重复预测同月扣款或工资。停用周期模式仅影响预测，不停止真实扣费。过期观察不会无限推演。

周期预测新增事件来源 `recurring_estimate`，新增金额 `estimated_recurring_spending_fen`。周期估计不计入“仅计划”余额线或 `planned_outflow_fen`。未回填的旧工资数据保留原有只读规则兼容；正常启动会先回填，因此保存的用户偏好优先，关闭后不会通过旧规则再次补造收入。

## 接口

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/foundations` | 本人的商户、别名、标签、辅助记录覆盖数量及说明 |
| POST | `/foundations/refresh` | 在一个数据库事务中回填当前用户的历史关联和周期候选，不修改原始账本 |
| GET | `/tags` | 本人的标签目录及绑定笔数 |
| PUT | `/transactions/{tx_id}/annotations` | `{ "tags": ["出差", "可报销"], "expected_version": 0 }`；空列表清除绑定 |
| GET | `/transactions/{tx_id}` | 本人单笔流水及元数据，可跨当前报告账期查看原单／对应流水；理财类型仍去资金流水查看 |
| POST | `/merchants/{merchant_id}/aliases` | `{ "name": "新名称" }`；已属于其他商户返回409，需显式归并 |
| POST | `/merchants/{merchant_id}/merge` | `{ "source_merchant_id": "M-…" }`；路径商户为保留目标；页面先展示影响并要求确认 |
| GET | `/recurring` | 已保存周期列表、观察流水ID、频率、金额、状态、偏好、版本 |
| PATCH | `/recurring/{stream_id}` | `{ "enabled": true, "expected_version": 2 }`；只支持有效的识别模式，订阅不能绕开取消流程 |

原 `BillQuery` 增加可空 `tag_id`，适用于报告、明细、订阅核对、账单问答和NOVA页面上下文。筛选其他用户的标签返回404。订阅核对中标签只筛选实际流水，当前计划仍按账户展示。现金流预测与账单的账期／标签筛选独立，账户范围沿用页面选择。

`BillTransaction` 新增 `merchant_id`、`merchant_name`、`original_tx_id`、`original_category`、`refund_link_source`、`refund_tx_ids`、`transfer_pair_id`、`paired_tx_id`、`recurring_stream_id`、`tags`、`annotation_version`。这些字段也进入消费依据和NOVA单笔查询。

NOVA增加只读工具 `list_recurring_records`，最多返回30组、每组最多5个观察ID，并明确总数及截断。没有新增标签、归并、资金执行或授权工具；名称和标签仍是不可信数据。

## 持久化与升级

新增 `bill_*` 辅助表，不给 `transactions` 增加列。启动时 `create_all` 建表，在种子／既有迁移之后回填，重复启动及手动刷新均可重入。转账、商户退款、订阅扣费／取消、卡片消费的辅助数据与原业务同事务提交，失败一起回滚。

写操作按用户ID排序取得专用锁，编辑使用乐观版本校验，记录元数据审计事件。别名和标签为本人私有，不能通过ID读取或更改他人数据。已归并商户保留历史ID和归并事件，页面暂不提供撤销；失效周期保留历史观察证据。当前支持人民币月度模式，尚无周／季度／年度模式、手工定义周期、部分退款匹配、外部银行商户主数据接入或自动学习标签。

本次在SQLite上验证了外键、重复升级和两个实际数据库会话并发编辑；PostgreSQL实现了相同锁流程，但本次未运行PostgreSQL验收。
