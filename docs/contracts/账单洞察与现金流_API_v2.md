# 账单洞察与现金流 v2

本次在原账单分析基础上增加消费变化追溯、订阅核对与确认处理、未来现金流及情景模拟。数据均来自本人有权访问的模拟银行记录。没有数据库迁移、自动取消订阅、自动转账或预算写入。

## 1. 消费变化追溯

`GET /api/v1/bills/analysis` 新增 `change_explanation`，原字段及查询保持兼容。

以当前账期和原上期对比范围内的已完成消费，按**原始商户文本 + 消费类别**分组。金额及笔数使用全部匹配流水，不受明细分页影响。

设本期金额 C、上期金额 P、本期笔数 n、上期笔数 m：

- 两期都有交易：次数贡献 = 四舍五入((n-m) × P/m)，平均单笔金额贡献 = C-P-次数贡献，出现／未出现贡献为0。
- 仅一期间有交易：差额全部放入“本期出现／未出现”，不伪造平均金额或消费频率。
- 先按整数分对次数贡献舍入，余数保留在平均金额贡献，使组内和全局差额精确对账。
- 返回各组金额、笔数、三个贡献、解释和本期／上期各最多5笔证据；证据含原交易ID及时间。
- 本期只有一笔、上期无记录、金额至少1000元且不是订阅，标为“本期新出现单笔大额”。这不证明永久一次性消费。
- 次数是交易笔数，平均单笔金额不是商品单价，不能推断商品购买量、合同价格或用户动机。
- 多次读取期间若差额不一致，返回 `BILL_CHANGED` 409 要求重查；不是不可变账本快照。

页面可展开商户、查看两期证据、选中流水后向 NOVA 询问。历史流水选择直接由服务端校验归属，不要求一定在当前页面账期内。

## 2. 订阅专项核对

`GET /api/v1/bills/subscription-insights` 接受原 BillQuery。账户及账期生效；类别筛选不生效，避免选择餐饮时隐藏订阅问题。响应为 as_of、items、notices。

每组以同账户和完全相同的商户名关联订阅关系与实际 `subscription` 流水：

- 最近单笔实际扣费比上期最近一笔增加，提示扣费变化，不认定合同涨价。
- 同金额相邻扣费在5分钟内发生，提示疑似重复。
- 同商户多条活跃关系，提示核对不同账户／套餐，不能认定重复订阅。
- 取消时间之后仍有扣费，提示核对；多条关系时不猜测每笔所属。
- 当前计划金额与最近扣费不同，明确区分计划与实际。
- 未找到关系时保留流水并提示未关联，不提供直接取消能力。

每组包含 subscription_ids、active_subscription_ids、实际金额笔数、当前人民币月费计划、flags、explanations 和两期证据样本。没有使用时长数据，因此不推断“闲置订阅”。

点击“核对取消详情”后跳转订阅页，复用 `cancel-preview` 的服务端短期签名令牌及当前 state_version。只展示确认卡；本人点击“确认取消”才调用原取消接口。预览和分析均不修改订阅。取消后刷新银行数据，下一次现金流不再包含已取消关系。

## 3. 现金流与情景

`POST /api/v1/bills/cashflow` 请求：

```json
{
  "days": 30,
  "account_id": null,
  "reductions": [{"category": "dining", "percent": 50}],
  "excluded_subscription_ids": ["SUB001"]
}
```

- days 为严格整数1–62，默认30；从**现实查询时刻**起覆盖完整天数，与历史账单查询的月份无关。首尾日期按照时间比例折算消费，时间区间左闭右开。
- account_id 可为本人有效储蓄账户或 null（全部有效储蓄账户）。其他用户返回404，信用账户／失效账户返回422。排除理财研究上下文账户。
- reductions 仅允许餐饮、购物、交通、娱乐、其他，严格整数0–100%，最多5项且类别不重复。
- excluded_subscription_ids 最多30个，每个1–40字符，不能重复，须为当前范围内有效人民币月度活跃订阅；其他用户、已取消或不在范围内统一404。
- 拒绝额外字段，包括 user_id，不接受客户端设置预测时钟。

### 基准口径

起始现金 = 有效储蓄账面现金 - 有效理财占款。占款已经扣除，未再把对应理财申购当成额外未来支出；不把信用额度、赎回应收或投资收益当现金。

计划项：

- 本人活跃 CNY/MONTHLY 订阅，按当前 next_charge_at 及原日期锚点推演，月末夹取不永久改变31日锚点。
- 已到期的订阅计划只提示待核对，不估算补扣；后续仍按当前月度计划推演。
- 本人 `WAITING_EXECUTION`、未请求取消、当前版本计划及 READY 操作中的未来人民币定时转账。草稿、取消、旧版本、已过期未执行计划不计未来已付款。
- 全部现金账户汇总时本人互转净额为0；单账户保留未来转入／转出。

估计项：

- 工资：最近三个完整月及当月截至现在的 salary 记录，同账户同雇主至少三个不同月份、每月恰好一笔、日期差不超过3天（或均为月末）、金额极差不超过中位数20%。按金额中位数及日期中位数推演，已到账月份不重复预测。收入明显不稳定时不估计。
- 日常消费：最近3个完整日历月的 purchase 记录，单类至少5笔且覆盖2个有记录的完整月份。总额除以完整观测日数，空日期按已记录0折算。外部未接入账单不包含。订阅专用类型不混入日常消费基线。
- 低／高余额线：分别用最近完整月份每日支出率的高／低值推演，包含无记录月份的0值，**不是置信区间**。工资仍是历史估计，未来不确定性未全部建模。

### 输出与情景

返回 as_of、end_exclusive、起始账面／占款／可用现金、计划流出、估计收入、估计日常消费、基准期末、情景期末、假设改善金额、日末最低余额、首次日末低于0的日期、spending_baselines、events、timeline、notices 和已应用 scenario。

events 区分 subscription_plan、scheduled_transfer、salary_estimate；工资带历史流水ID。timeline 包含仅计划、基准、用户假设、历史高／低支出余额线。

情景减少只应用于合格消费基线；排除订阅只应用于预测范围内对应计划扣费，不删除实际历史交易、不自动取消、不声称节省已经到账。页面修改假设后会提示重新计算；展示数值属于上一次已应用情景。

若数据不足，不补造消费或收入，明确提示未估计；未估计不等于未来必定为0。负余额提醒按日末估计，不能替代日内、未知付款及实时风险检测。

## 4. NOVA

`get_bill_analysis` 复用新增解释，保留精确金额，返回最多10组驱动并附总数／has_more。新只读工具：

- `get_subscription_insights`：沿用页面账户、账期；最多返回20组，附总数和截断标记。
- `project_cashflow`：接受上述严格情景；省略账户沿用账单页账户，显式 null 清除；最多返回20个事件并声明总数。按现实现在预测，不沿用历史账期作为时钟。

服务端身份独立注入，不接收模型 user_id。工具不生成订阅取消令牌、不确认、不执行写操作。回答须区分计划、估计与假设，不把重复提示当欺诈结论。离线有限支持“未来7天现金流”“情景减少餐饮20%”；复杂假设可在面板设置或由已配置模型调用严格工具。

## 5. 独立演示

```bash
.venv/bin/python scripts/create_bill_insights_demo.py --output /tmp/bill-insights-demo.db
DATABASE_URL=sqlite+aiosqlite:////tmp/bill-insights-demo.db LLM_MODE=offline \
  .venv/bin/python -m uvicorn backend.app.main:app --env-file .env --host 127.0.0.1 --port 8000
```

脚本只创建不存在的新数据库，不覆盖运行账本。合成2026年7月至10月工资和消费、十月新大额交易及音乐重复扣费；初始余额不与合成历史对账。

登录张三，选择2026-10；查看变化追溯与订阅核对；现金流中设置餐饮减少50%，假设排除音乐订阅；核对差额；点击订阅取消详情并确认，再返回验证计划移除。基准随现实时间滚动，具体现金流金额会变动。
