# NOVA 当前任务补充与切换

2026-10-23，本地实现；不改变银行确认、MFA及成交规则。

用户可直接输入当前任务的对象、金额、份额、预算、候选或下一步，无需点击“用对话补充此卡”。点击表单或勾选持仓会指定对应步骤；否则使用本人当前对话中服务端记录的活动任务。刷新恢复引用，多个旧任务无法唯一确定时先询问。持仓→赎回、推荐→申购和规划内部先赎后买是同一任务后续。独立查询可以插入，不放弃原任务。

复用现有结构化路由的 `task_action` 区分 continue、read、switch、unclear，没有增加额外模型调用。跨业务写工具还会检查当前任务；理财子模型提出不同业务目标、转账子模型提出新转账时，提交前再次检查。路由及子模型均只提出意图，参数依据、本人归属、资格、金额和对象引用继续由现有共用层及银行核验。

明确转向新操作时，服务端生成确认卡，列出当前任务和目标任务。未确认不结束原任务、不创建目标操作；取消保留原输入。确认后先安全结束未提交草稿、使旧预览和授权失效，再用原始请求办理目标操作；仍需该操作本身的手动确认及MFA。自然语言不代勾“本人已阅读并同意”，YELLOW本人手动点确认，RED额外强验证。

`nova_task_flows` 按本人和对话加密保存活动引用与一次性切换提议，提议有效10分钟，删除对话同时清理。确认请求使用 `task_switch_token` 和 `accept_task_switch`，不接受模型代传。卡片或输入变化、版本冲突、过期、重复确认均不能启动目标。确认处理先CAS领取，连接中断不自动重放；不能安全结束的已确认、已到账或未知结果留在原卡片核对。完成的金融操作正常保留，不能因切换改写。已完成任务不再要求放弃草稿。

切换提议和处理中暂停串行队列推进；确认成功停止原队列后续，再办理新目标。取消提议恢复原队列。确认不等于调整原队列顺序；仍不提供用户改序。

接口：聊天及SSE响应提供 `task_switch`（token/current_label/target_label）；GET `/api/v1/nova/task-flow/{session_id}` 恢复待确认卡。聊天字段为严格schema，身份来自登录态。确认期间用户仍可修改表单，但新的修改会使旧切换确认失效。
