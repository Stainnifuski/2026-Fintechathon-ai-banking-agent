# NOVA 理财任务与可信卡片 v0.1

2026-10-21。本机接线实现；是否部署、验证范围见同日验收记录。复用现有 DeepSeek、理财配置与银行接口，不新增账本、供应商或授权通道。

## 模型与卡片职责

NOVA 路由新增 `wealth`，单个理财目标只开放 `manage_wealth_request`。工具参数严格为空对象；专用子模型依据原文、脱敏历史、服务端本人任务和卡片可见产品解析最多四个意图。固定指引在 `backend/app/skills/wealth/SKILL.md`。模型不能传主体、付款账户、确认、验证码或执行参数。

支持资产、持仓、收益日历、详情、比较、本人问卷、目标推荐、规划、指定产品申购、独立普通／快赎和草稿修改／恢复。类别不明先澄清；精确产品身份从银行目录重读，同名或缺失不猜。序号只绑定所指卡片最近保存的可见候选，重新核实代码和版本。类别请求不能被模型擅自转成具体产品购买。

卡片复用 Wealth、ProductPicker、StructuredPortfolioReview、TargetPurchase、RedemptionDialog 和 PlanExecution。缺有效评估时本人在正式问卷作答并确认，随后继续原意图。目标推荐没有资产配置计算；规划使用现有增量模型和三个金额输入。换批、跨批选择、详情、比较、逐产品金额、申赎结构化确认和统一第二因素都在卡片完成。候选读取与资金写入仍有原服务端资格、账户范围和幂等检查。

卡片按匹配、各候选池、实时已选、现金预算、申购金额、配置建议、交易明细和本人确认分别展示。用户点击“用对话补充此卡”后，聊天附带 `wealth_task_id` 与 `wealth_stage`，服务端核实归属。自然语言可修改明确参数、引用当前候选序号，或推进非授权的核对与预览；更新时保留其他已选产品、预算和金额。YELLOW 必须本人手动点击卡片确认；RED 必须本人在卡片确认并完成独立 MFA。“本人已阅读并同意”不能由聊天代勾选。服务端不生成可执行的交易确认指令，前端交易卡没有自然语言确认或验证处理器。

可用现金与有效风险评估状态直接返回文字，不新建操作卡片。展开中的原有评估卡不会因升级自动删除。

2026-10-22 增加参数依据：子模型的现金预算、逐产品申购金额、赎回份额／市值／比例须能从本轮原文解析，分别携带cash_quote、amount_quotes及redemption_quote。多产品金额的quote还需包含对应名称、代码或明确序号；资产、留存、投资预算分别核对，不把“我有两万元”变成“投入两万元”。缺依据返回PARAMETER_NOT_GROUNDED，不新增草稿、订单或占款。服务端已保存且本轮未改动的字段仍可继承。子模型自由追问替换为受控补充提示。最终文字、普通接口、流式与保存历史使用 [统一事实边界](../security/hallucination_guard.md)，卡片原有本人确认和MFA不变。

## 会话接口

所有路径前缀 `/api/v1/nova`，主体仅来自 JWT；每次核实聊天会话和理财任务均属于本人。

|方法及路径|用途|
|---|---|
|GET `/wealth-sessions/{session_id}`|恢复本人会话全部理财卡片，包含草稿指令、版本、资金范围、选择引用和执行方案引用|
|POST `/wealth-sessions/{session_id}/cards/{task_id}`|版本化保存方案引用，放弃草稿，暂停／恢复后续步骤，或修改完全未提交的方案|
|POST `/wealth-sessions/{session_id}/cards/{task_id}/view`|保存有限的可见候选／所选产品引用，用于多轮指代和重载恢复；不是银行事实或交易授权|

状态请求包含 `version`，可选 `execution_plan_id`、`closed`、`paused`、`reset_draft`。额外字段（包括 proof、accepted、user_id）拒绝。任务版本不同返回 `STALE_WEALTH_CARD`。只读视图写入也检查版本，但不消耗授权版本；后续选品必须重新验证，不把前端快照当资格证据。

视图支持候选所属板块、本人所选、现金输入类型与金额、逐产品金额，不接收确认或验证码。短用户锁串行化视图和动作会话引用写入，避免相互覆盖。

`DELETE /api/v1/bank/nova/conversations/{session_id}` 在本人归属校验后永久删除聊天、相关 NOVA 状态与已关联的理财草稿缓存及请求回执。前端先显示不可恢复确认弹窗；银行成交、账务、授权及审计事实保留。删除不代表撤回已提交交易。新理财动作保存其缓存会话引用供后续清理；未建立关联的历史缓存不推测归属后删除。

`/nova/chat` 和 SSE 最终响应在有任务时附加 `wealth_cards`；没有理财卡片时保留原响应结构。旧转账会话版本和理财卡片版本彼此独立。任务桥接复用 `wealth_conversations` 的专用 NW 标识和 `wealth_chat_requests` 的专用请求键；不向转账 session.state 填入理财状态。

同一用户、会话和请求号重放返回现有任务；请求号换原文报幂等冲突。模型和银行读取在短写事务之外；最终用户锁内重查请求，再持久化，防止并发同号产生多个草稿。

## 准备、恢复与授权

卡片准备请求携带 `X-Nova-Wealth-Task`，服务端在准备前验证任务归属、未关闭／未暂停。目标申购、批量赎回和规划准备返回前保存执行 Plan 引用；客户端确认引用已保存后再开放可信操作。规划 `/plans/{id}/continue-purchase` 同时把原卡片连接到新 BUY，响应丢失时仍从服务端找回。旧方案与原操作号仍保留。

恢复后读取 `/wealth/plans/{id}/progress`，不重放聊天为交易。未知／部分结果只能原号核对。全部 SELL 真实到账后，既有 continue-purchase 重新核对现金、份额、费用和额外变化，再创建全新 BUY。第二阶段有独立确认和独立 MFA；失败资金留现金，不自动追加赎回。

暂停调用既有任务控制，使未提交授权失效并阻止新提交及规划接续；恢复后重新核对。修改完全未提交的方案会使旧授权失效、旧 Plan 标为 CANCELLED，再回到草稿；已提交、未知或已消耗授权拒绝修改重下，不回退成交。这是取消未提交草稿，不能恢复已取消的订单等待／撤单页面。

验证码只进入统一 SecondFactor 与验证接口。聊天中明确标为验证码的六位数字在进入历史和模型前隐藏，六位基金代码保持。本人答案、验证码或 MFA 成功状态不在工具 Schema、卡片视图引用中流转。

## 本期边界

### 单任务按步展示与回退

候选未完成时不展开金额或交易卡；完成的步骤保留摘要，只有当前未完成步骤展开输入。手动填写后可用卡片继续；自然语言已经明确具体产品及完整金额、规划选品和预算、或单只赎回输入时，可以自动推进到非授权核对／预览，无须重复说“下一步”。风险问卷仍本人填写，YELLOW 手动确认、RED 本人确认加 MFA 不变。完整输入不代表授权。

`view.completed_stages` 只保存界面进度，不构成资格或授权依据。候选池是独立分支，共同依赖之后的资金、配置及交易步骤。当前未完成步骤内的补充是普通修正；修改已完成步骤或已经准备交易的上游输入，转为回退提议。自然语言的 `edit_kind=backtrack`／`target_stage` 也只生成提议。

卡片状态可传 `backtrack_stage` 提议回退；响应 `pending_backtrack` 列出目标及重置范围，并返回绑定当前任务版本的 token。本人手动点击卡片后提交 `backtrack_token` 和 `accept_backtrack`。取消保留原输入；确认才撤销未提交方案及旧授权，清除受依赖影响的后续输入和进度，增加 `draft_epoch` 并要求重新填写／核对。无依赖的其他候选池保留。旧 token 或版本不能重放。待确认期间，结构化准备、确认、MFA 与提交均拒绝。

服务端检查原执行状态和 SELL→BUY 历史，已成交／已到账／提交中／结果未知禁止回退改写。新卡片保存已完成阶段引用；旧卡片从原 SELL 的幂等接续结果反查 BUY 祖先。后续申购失败留现金，不撤回已到账赎回。新调整应基于当前资产新建任务。

### 明确暂缓

按用户最新指示：一句话多个理财操作的串行办理，以及跨场景一句话多操作、自主规划顺序、告知顺序并允许用户改序，均只记录为后续工作。须先完成并验收单任务步骤控制后再讨论，不在本轮实施或声称已经支持。

固定806离线包保持；夏普排序、历史基础与后台批量增量继续暂缓。没有新增行情日更或全池采集。NOVA 卡片按需展开较多现有工作台能力，前端延迟加载理财模块，避免所有页面首屏加载完整理财图表。
