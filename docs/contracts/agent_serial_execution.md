# NOVA 多操作串行办理

一句指令最多8个目标。前置路由生成DAG，每项目标必须逐字对应本轮原文的独立连续片段；重复或重叠引用拒绝。服务端稳定拓扑排序：依赖优先，无依赖按原文顺序。界面告知顺序，不要求批准顺序，也不提供改序接口。

## 执行与授权

只有当前目标进入原业务Agent。查询得到事实后可自动继续；需要候选选择、正式问卷、交易确认或MFA时等待本人。交易草稿、预览、验证码验证通过均不是成交。理财依据本人WealthPlan完成态，转账依据银行任务SUCCEEDED，卡片操作依据COMPLETED。规划SELL完成仍等待独立BUY完成；两次本人确认和两次MFA保留。失败、未知、关闭当前草稿、部分完成或连接中断均不重放已受理操作，后续目标停止推进；资金以银行账本为准。停止后续不会撤回成交，也不会替用户取消当前业务草稿。

理财目标推荐不进入配置模型。自然语言仅补充当前目标或推进非授权步骤；YELLOW须卡片手动确认，RED须本人同意及独立MFA。队列和模型都不能代勾、确认、验证或执行。

## 持久化与恢复

`nova_execution_queues`按本人会话隔离，保存加密原文片段、目标、状态、真实业务引用及有依据的返回结果。它是助手编排状态，不是银行订单、占款或新账本。每步独立稳定请求号；CAS版本和短租约防重复启动。运行中连接中断后暂停并要求核对原任务，不自动重试可能非幂等的业务工具。空闲等待轮询仅观察，不更新版本、不请求模型或外部行情。

打开NOVA时每4秒核对一次待办队列，确认当前业务终态后才启动下一项；收起或离开对话暂停自动接续，重新打开恢复。后续读取会重新使用银行事实；对象列表引用继续遵守15分钟有效期和本人归属规则。删对话同步清除队列，保留银行账务及审计。

页面bootstrap的`workspace/reset`仅重置工作台草稿。根据服务端本人NOVA会话、理财卡片及方案的持久关联，保留这些方案/任务图和有效授权；不接收客户端“保留”标志，不保护他人会话冒用的ID。授权自身的有效期、本人确认和MFA要求保持。

顺序摘要引用原始指令；本人后续修正的交易参数，以当前可信业务卡片及最终手动确认的明细为准。

## 接口

| 接口 | 含义 |
|---|---|
| GET `/api/v1/nova/execution-queues/{session_id}` | 本人会话队列，只读 |
| POST `.../{session_id}/advance` | `{version}`，核对当前状态并按序推进，不能携带授权或MFA |
| POST `.../{session_id}/stop` | `{version}`，停止后续，不撤回成交 |

chat/SSE及队列接口返回`execution_queue`，含顺序、逐项状态和已核实结果。队列接口不能传任意命令、金额、目标、顺序或用户身份。

## 跨场景范围

持仓查询及赎回共享同一个理财task_id：查看持仓是主任务，赎回是可选子任务。勾选后可自然语言继续，或由串行目标进入；未勾选/未填数量时在该任务等待补充。选择引用在使用前重新核对本人银行持仓，不能变成自动成交授权。

使用同一队列协调目前已注册工具：理财完整办理、转账草稿及原可信确认/MFA、卡片操作预览及卡片页手动确认/MFA，以及账户、账单、订阅、日历和店铺的已有查询能力。比如“赎回到账后给李四转100元，再查可用现金”在赎回真正完成前不会生成转账草稿，转账成功前不作最后查询。

订阅取消/扣费、店铺付款等没有NOVA写工具的功能，仍使用原业务页面；本次不以队列冒充这些场景已经接通自动写操作。用户调整顺序暂不实现。夏普排序、全池历史及增量缓存仍不在本次范围。
