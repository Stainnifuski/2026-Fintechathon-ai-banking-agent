# NOVA 共用语义、上下文及对象引用绑定

基于 main `4442c97578d8ddab6992ada4d8e6b2b9df64834e`，2026-10-23 本地优化。语义理解继续复用现有 DeepSeek 模型，不增加第二个判定模型。

## 共用流程

1. 原有路由、业务子模型理解语义，提出字段、对象及原文片段；不得输出确认、验证码或可执行授权。
2. `semantic_bindings` 将字段映射到注册的 `FieldSpec`，使用最长字段名消除嵌套词冲突；新同义说法可凭完整语义原文片段提出解释，不要求仅使用固定词。已有明确字段或资产/投资含义冲突时拒绝，不能让模型覆盖。
3. 数值单独通过 `parameter_grounding` 验证：精确数值、单位、原文片段、否定语境一致。全角/半角、中文数字、千位分隔符、百分之五十/一半等可规范化；不能从基金代码、历史回答、余额或其他产品的数值造金额。
4. 省略字段仅继承当前明确焦点卡片的服务端状态；`TrustedFrame` 保留任务号、版本、字段和本人最新输入。`view_context` 优先于旧命令。没有焦点或存在冲突时询问，不猜字段。数值比较使用 Decimal，`100` 与 `100.00` 不作为不同金额。
5. 序号引用使用同一解析器，中文/数字/全角及个、只、支、张、笔、项等量词等价，采用1起始顺序；否定的序号不作为选择，第二季度不作为第二个对象。具体名称可规范化空白、字形；银行ID不做相似匹配或大小写替换，同名、多对象、越界、缺快照必须澄清。
6. 所有参数再由原业务服务重新核对本人归属、资格、报价、持仓、资金与版本。回退依据实际修改的字段确定依赖范围，模型声称的当前阶段不能绕过已完成步骤。仍由本人手动确认回退；成交/到账屏障及独立MFA不变。

## 已接入范围

- 理财：现金三字段、候选序号、每产品金额引用、当前卡片省略输入、视图/命令同步及参数依赖回退。
- 卡片操作预览：单笔/每日/信用额度使用同一字段契约；`value_quotes` 按字段提供原文，避免多金额交换字段。只生成预览，不确认执行。
- NOVA 通用工具：卡片、订阅、流水、日历、花店/蛋糕店商品及订单的详情/卡片预览统一对象引用。页面明确选中对象优先，仍由所属银行/业务服务验证归属；跨轮序号使用本人本对话最近实际展示列表。
- 转账：继续使用现有持久任务与可信焦点、历史流水核对；金额原文检查复用共用文本规范化。收款手机号、银行卡号及备注不模糊替换，任务确认/MFA入口保持。
- 其他工具原有筛选继承保留：未提供字段与显式null不同。共用层只替换真正解析出的字段，不能把默认值重建成用户明确输入。

未来工具登记字段和引用提供者即可复用这些边界，不复制三组特例规则。业务适配器仍负责当前对象、资金范围及版本的真实性；不存在可接受任意字段或授权的万能解析入口。

## 跨轮对象缓存

`nova_reference_contexts` 由正常增量启动创建，按对话主键、本人归属管理，payload使用现有会话加密方式。仅保存注册提供者的对象ID、显示名称/掩码及必要版本，最多7种列表、每种最近可见10项，不存余额、金额、验证码或授权。每个列表15分钟有效，新列表替换同提供者；读取失败会使旧成功快照失效。内部未展示的刷新不能改变用户原先看到的序号顺序；新结果展示后才更新跨轮快照。

缓存与相应最终对话轮次一起保存；查询对象时重新调用所属业务读取最新详情。删除对话同步删除缓存。过期快照不再用于解析，下一次写入替换；没有新增定时采集、行情刷新或自动金融执行。
