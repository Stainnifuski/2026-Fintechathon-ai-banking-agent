# NOVA任务卡、时间线与人工接管

单卡或多步骤卡、业务状态机和多目标串行依赖保持各自规则。共用展示层统一任务标题、摘要、状态、折叠、结束入口、错误及确认区域，采用NOVA紫色主题。已完成、已取消、失败、已发送、待核实分别展示，不把草稿结束写成交易成功。

## 时间线和确认

自然语言更新后的卡片跟随本轮回复；直接卡片操作产生的后续内容跟随原操作。稳定的表单实例挂载到新展示位置，普通更新和移动不清空本地输入。历史任务留在原位置，终态压缩为摘要。展示事件只记录实际交互，不伪造用户自然语言，不作为银行受理或授权证明。

删除对话、结束草稿采用NOVA面板内居中的内部确认框，透明交互阻挡层不添加黑色背景；取消左、确认右，弹出前关闭历史菜单。切换操作和回退步骤保留对话内确认卡，列明目标及重置影响。已有银行受理、成交和待核实操作按原业务服务处理，不因关闭展示而撤回。

## 一个对话一个活动操作

模型结构化路由判断继续、只读插问、切换或澄清；服务端按本人实际任务引用核验。补充当前信息复用原任务；不同目标先提议切换，未确认前保留原任务。辅助查询不结束当前操作。一句话多个操作仍由原队列逐项启动，完成屏障、失败及未知状态阻断保留，不新增用户改序。

表单尚未提交的填写在下一次对话前保存为加密的显示草稿，供理解当前选择使用；它不是银行事实或本人授权。字段和业务资格仍由原服务校验。草稿接口拒绝验证码和授权字段，并限制字段白名单和大小；完整手机号、银行卡号不放进路由的未提交表单摘要。未确认或验证的任务不能通过模型补充绕过确认。

## 人工接管

顶部入口只对当前可接管操作启用。接管前等待理财显示草稿写入完成，保存其他任务的当前非授权输入；服务端验证本人会话、真实任务和队列租约。一个事务记录接管归属、停止当前Agent步骤、取消全部尚未开始的后续步骤，并留下明确说明。已完成步骤和银行事实保留。重复请求读取原回执，冲突请求拒绝；连接中断先核对同一回执，不换操作号重放。

对应工作台顶部显示原任务继续区，复用原业务组件和同一个银行操作／方案引用，不复制为新交易。移动时保留表单实例，刷新后可从原对话“继续人工办理”恢复加密的非授权填写。验证码清空，本人同意不自动勾选；原银行版本、权限、风险、幂等、审计和MFA不变。NOVA原卡只展示接管摘要，不再接收该工作台的后续结果；新的对话操作可以正常开始。银行概览仍可正常读取同一共享账本。

确定失败保留原任务和队列；结果未知则禁用原办理入口并核对原回执。没有为接管增加可绕过银行确认或直接执行的模型工具。

## 统一长文本输出

最终模型回答协议增加`layout=sections|list`，由统一提示选择证据顺序和布局；后端将核实的范围、金额、对象、明细和限制渲染为Markdown段落／列表，长证据按原有句界分隔。模型不能写自由金融事实，也不能隐藏失败或风险提示。无需第二次模型润色，不逐个场景重写答复；历史已保存消息不重新生成。

## 接口

均在`/api/v1/nova`下，使用当前登录用户并核对会话归属：

- `GET /presentation/{session_id}`：任务标识、目的工作台、实际状态、时间线位置和接管回执；`Cache-Control: no-store`。
- `POST /presentation/{session_id}/draft`：保存`key/draft`，仅显示草稿，无业务执行。
- `POST /presentation/{session_id}/position`：保存`key/request_id/existing`；直接操作只添加助手事件，不制造用户消息。
- `POST /presentation/{session_id}/release`：`key/mode/request_id/draft`；`mode=manual|cancel`。接管不调用银行取消，结束未提交任务须经过原业务可取消检查。
- `POST /presentation/{session_id}/candidate`：人工接管后的转账候选按本人原候选ID选择，不调用LLM，也不直接执行转账。

加密资料沿用`nova_task_flows`，随对话清理；没有新银行账本或破坏性迁移。运行数据库、私有配置、接管测试录入和模型凭据不随源码发布。
