# 原版前端优化（分支 `原版优化`）

基于 main `90fe5f2`，只改原版前端 `frontend/` 的界面层：没有改后端接口、数据结构和业务逻辑，没有增加或去掉原版已有的功能；NOVA 的“调试模式”保持原样。另附一处仓库配置修复（`.gitattributes`），见最后一节。

## 改了什么

### 1. 转账与收款页

**新建转账**

- 标题旁改为“选择收款人”“管理”两个文字按钮，打开的仍是原来的联系人面板。
- 付款账户显示为“活期账户 6222 **** 8842 · 可用 ¥50,000.00”。
- 收款账户（手机号 / 银行卡号）、执行时间（立即 / 定时）改为分段按钮；收款账户默认选手机号。
- 卡片内校验：收款人必填，金额必须大于 0 且最多两位小数；错误直接显示在卡片里，不再只出现在页面顶部。

**发起收款**

- 付款人改为直接展开的勾选列表（原来是下拉框）。
- 收款账户和金额同一行；AA 均分改为复选框，开启后金额标签变为“AA 总金额”。
- 预览“向 N 人各收 ¥x，合计 ¥y”，按“分”计算；无法均分到分时直接提示。

**最近流水**

- 改为独占一行的表格，每页 5 笔，可翻页，标题旁显示总笔数。
- 金额带正负号和千分位，状态用彩色标签；补齐商户收款、退款支出、模拟入账等类型的中文名。

**布局**

- 原来两列网格按行对齐，矮卡片下面留出大块空白。现在左右两列各自往下排：左列“我的账户、发起收款”，右列“新建转账、收款申请、即时转账对话”，“最近流水”在下方占满整行。
- 窗口较窄变成单列时，顺序为：我的账户 → 新建转账 → 发起收款 → 收款申请 → 即时转账对话。
- 顺带修正：“我的账户”里的信用账户原来显示英文 `credit`，现在显示“信用账户”。

### 2. 侧栏导航图标

只把彩色圆角方块里的白色符号换成线条图标（概览、转账与收款、账单洞察、卡片、订阅、理财、生活服务、操作记录）。方块本身、每个场景的颜色和尺寸都没变。

### 3. NOVA 吉祥物动画

- 对话里还没有消息（显示“今天想办理什么？”）时，球在大屏正中间；在输入框打字时不动。
- 发出消息、NOVA 回复时，球平滑移到右侧，进入思考状态（转速加快、颜色变亮）。
- 收起 NOVA 时，无论是否开始对话，球都移到 NOVA 面板头部；展开时移回去。
- 页面上只有一个球，一直显示、一直在动。每次换位置都沿直线平滑移动（约 0.65 秒），不再闪现。

实现：原来的 `.nova-mascot` 元素改为“落点”，位置仍由原有 CSS 决定，不再绘制；新增一个悬浮层画球，每帧读取落点位置并平滑过去。切换大屏/侧栏时整页有一次 View Transition，进行期间球先停在原处，结束后再出发，避免跳变。动画引擎 `mascot-engine.js` 没有改。

### 4. 金额统一千分位

全站显示的金额统一为 `¥50,000.00` 格式（未知金额显示“—”或“未知”，不按 0 显示）。涉及转账与收款、订阅、卡片管理、商户工作台、生活服务、操作记录、NOVA 对话里的转账/卡片/店铺/订阅任务卡，以及理财（共用的 `money()` 函数）。

没有改的：输入框里预先填入的数值（例如卡片限额、收款金额）、百分比、提交给接口的数据——这些加逗号会出错。

### 5. 重新绑定验证器前先确认

后端 `/auth/totp/enroll` 一被调用就会重置密钥、作废已绑定的验证器。原来已绑定的用户只要点一下右上角的锁形按钮，再点取消，验证器就失效了。现在：

- 已绑定时点击，先弹出“重新绑定验证器”确认：选“保留当前验证器”不发任何请求；选“作废并重新绑定”才调用接口并显示二维码，按钮随即改为“绑定验证器”。
- 从未绑定，或转账验证时提示尚未绑定（`TOTP_NOT_ENROLLED`），仍直接进入绑定。

## 怎么使用

1. 拉取并切到分支（先提交或暂存手上的改动）：

   ```bash
   git fetch origin
   git switch 原版优化
   ```

2. 按 `AGENTS.md` 重建并等待健康（不会清库，账本保留）：

   ```bash
   docker compose up -d --build --wait --wait-timeout 300 backend frontend
   ```

3. 打开 http://localhost:3000，按 `Ctrl+F5` 强制刷新，用张三 `13800000001` / `password123` 登录。

### 逐项查看

- **吉祥物**：登录后球在正中间；问一句只读的问题（如“现在几点”），球移到右侧；点右上角“收起 NOVA”，球移到头部；再点“展开 NOVA”，球移回来。想再看一次正中间，点“新建/历史对话”新建对话。
- **侧栏图标**：左侧导航的彩色方块里是新的线条图标。
- **转账与收款**（先收起 NOVA，再点左侧“转账与收款”）：切换手机号 / 银行卡号、立即 / 定时；不填收款人或金额填 `1.234` 后点“生成确认信息”，卡片内会提示；在“发起收款”勾选联系人、填金额，看每人金额和合计。生成确认信息只会出现待确认的任务卡，不会扣款。
- **最近流水翻页**：需要 6 笔以上流水。没有的话，可以在订阅页点几次“模拟扣费”（会真实减少演示账户余额）。
- **金额千分位**：转账页“我的账户”、卡片页的限额都是 `¥50,000.00` 这种格式；商户工作台可用花店账号 `13800000007` / `password123` 查看。
- **重新绑定验证器**：先点右上角锁形按钮，用 Google Authenticator 等 App 扫码完成绑定；再点一次，会出现“重新绑定验证器”确认，选“保留当前验证器”不会有任何变化。绑定后，当日累计超过 ¥1,000.00 的转账都需要这个验证器，请保留 App 里的条目。

## 仓库配置修复：Skill 文件换行符

main 上的安全提交 `90fe5f2` 会在后端启动时，用 `backend/app/security/skill_hashes.json` 核对 8 个 `backend/app/skills/*/SKILL.md` 的 SHA-256。哈希是按 LF 换行计算的；Windows 上 git 默认 `core.autocrlf=true`，检出时会把这些文件转成 CRLF，后端因此报 `SKILL_INTEGRITY_REJECTED` 拒绝启动。

`.gitattributes` 新增：

```
backend/app/skills/**/SKILL.md text eol=lf
```

这一处单独提交，可以直接挑到 main。已经检出过的 Windows 机器，拉取后需要重新检出这几个文件，才会变回 LF：

```bash
rm backend/app/skills/*/SKILL.md
git checkout -- backend/app/skills
```
