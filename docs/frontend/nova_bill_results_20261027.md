# NOVA 账单查询可视化

日期：2026-10-27。

## 展示范围

账单查询采用「摘要、结果卡、完整依据」三层结构，沿用 NOVA 紫色主题、留白和圆角。查询卡为只读结果，不增加确认、结束任务或人工接管按钮；账单修改仍沿用原确认卡及统一任务外框。

| 查询 | 默认展示 |
|---|---|
| 账单分析 | 净消费等指标、消费分类条形图、消费趋势折线图、主要变化与待核对提示 |
| 交易列表及单笔详情 | 金额、类型、分类、标签与关联情况的分项列表 |
| 预算查询 | 预算、已用净消费、剩余、月底估计、实际使用比例及进度条 |
| 异常、订阅 | 核对状态、原因、计划与实际扣费的对照 |
| 现金流 | 仅已知计划、基准估计、假设情景三条曲线与事件列表 |
| 周期收支、预测复盘 | 计划来源、纳入预测状态、预测与实际净变化；未结束不显示最终误差 |
| 商户、标签、分类目录及商户变更预览 | 目录列表、关联数量和只读预览状态 |

只有本轮全部可展示结果均为成功的账单查询且事实核验通过时，完整文字才默认折叠。混合业务、部分失败、目标规划和队列回答保留原正文，防止隐藏失败或未处理的目标。旧会话没有结果快照时继续展示原文字。

图表采用现有 ECharts 运行时和可测量后初始化的封装，按需加载；图表同时提供可展开数据表。工具提示绘制为 canvas 富文本，不把商户名称插入 HTML。用户名称、备注和标签通过普通 React 文本展示。

## 数据与跳转

结果卡由服务端银行工具返回的数据生成，不解析聊天文字中的金额，不让模型生成图表代码。金额保持整数分，缺失值显示尚未核实。预算占用超过 100% 时进度条只限制视觉长度，实际比例和负剩余金额照常显示。

账期、账户范围、标签及分类条件、北京时间、数据不足与预测假设随卡展示。流入流出与消费原额、退款、净消费分别核对。现金流的情景差额不是实际节省或到账。

分类图、行记录及卡片底部均可进入对应工作台。分类和流水链接传递原查询范围或明确的交易引用，再由现有银行接口读取当前数据；单笔交易进入其原交易月份。工作台更新不覆盖历史卡片。查询时快照始终保留原截止时间。

## 接口和保存

- 聊天完成响应增加可选 `bill_result_cards`；多操作队列的后续账单查询也保存并返回结果卡。
- `GET /api/v1/nova/conversations/{session_id}/bill-results` 返回本人此会话的结果快照。其他用户与不存在的会话均拒绝访问。
- 新表 `nova_bill_results` 归入 assistant 审计域；payload 使用现有会话密钥加密。标识绑定用户、会话、请求和证据内容指纹；相同结果重复保存不会新增卡片。删除会话清理快照，保留银行交易及审计事实。
- 卡片字段包括 `result_id / request_id / kind / position / title / summary / as_of / scope / notices / metrics / charts / rows / total / has_more / target / evidence_id / content_hash / compact_reply`。卡片不包含执行凭证，不注册成模型工具。
- 原聊天文字与核验依据继续保存，结果恢复失败时保留文字。新增表由现有启动建表流程增量创建，不重置或迁移账本。

接口实现没有改变 NOVA 意图路由及语义抽取，不增加自然语言关键词或正则解析。
