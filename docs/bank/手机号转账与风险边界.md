## 手机号和备注规则

只接受完整中国大陆手机号，容许 `+86`、空格、连字符。号码作为字符串，集中规范化为11位字符串后精确比较。姓名与号码同时提供时必须指向同一客户。一人多账户返回脱敏候选，不自动选首个。会话候选绑定用户、会话版本、查询槽位及10分钟有效期；修改号码立即清除候选，选择时重新查询。计划绑定规范化号码和银行返回的账户；确认后映射变化会阻断受理或银行提交，不会自动改收款账户。完整手机号不出现在候选标签或浏览器内部令牌中。

备注主字段仍是 note。来源可为 manual、automatic、cleared；旧客户端不传来源时原有 null 语义保留。自动备注仅在明确用途表达中使用有限固定词，否则为“转账”；手动备注优先，显式清空不再自动回填。最多256字符，拒绝纯空白和控制字符；HTML、SQL 和命令文字作为数据落账并按纯文本展示。修改创建新计划和摘要，旧授权撤销，受理后不可改。双边流水、计划、操作快照和确认卡使用同一最终备注。

## 金额、业务日、事务与幂等

权威命令金额为正整数分，上限2,000,000,000分；布尔、非有限值、非法精度和不支持币种拒绝。旧余额/流水 Float 字段仍保留以兼容演示库，读写时通过 Decimal 严格转为整数分，历史异常数值失败关闭。银行日限额按付款账户、`BANK_BUSINESS_TIMEZONE`（默认 Asia/Shanghai）当天已完成的转出流水计算。每日显示额也按同一口径投影；旧 daily_transfer_used 列不作为跨日权威来源。

银行提交在一个数据库事务中检查主体、双方客户和账户状态、余额、日限额、AA 绑定与同号摘要，再写入银行操作、双方余额及两条流水。SQLite 用空更新取得跨连接写锁；PostgreSQL 按账户 ID 顺序取行锁，当前未在 PostgreSQL 环境验证。任一步约束冲突会回滚事务并映射稳定业务错误。相同操作号/参数只返回一份结果；同号改账户、金额、币种、备注或手机号绑定被拒绝。重放前仍检查付款账户归属。银行成功但响应丢失时，5号继续 UNKNOWN/RECONCILING 并用原编号查询，不能新编号重付。

## 风险接口与分工

4号提供可信的业务日用户已完成转出额（所有账户汇总）、账户状态和身份映射；银行日限额与用户授权阈值分开。3号现有 `precheck_risk(db, user_id, amount_fen, daily_transfer_used_fen)` 结合应用 HELD 占用返回 YELLOW 或 RED：累计含本笔 ≤100000分为黄色明确确认，超过为红色强验证。成功计入银行事实；HELD 在途占用不因跨日自动释放；SETTLED 不重复计算；失败/取消 RELEASED。5号在计划创建和受理前分别调用，受理时按用户数据库行锁串行化复评与占用。风险异常或未知等级失败关闭；红色强验证当前返回501，不能执行。

给3号后续接入的最小目标契约：输入用户、操作号、计划版本、参数摘要、付款账户、整数分金额、币种、业务日期、已完成用户累计、未决占用（排除本操作已持有的占用）、control_epoch；输出等级、所需动作、稳定原因码及策略版本。若提供 decision_id/有效期/证明，须绑定以上操作和版本。风险策略升级后需重新验证，不能沿用黄色授权。当前实现尚无完整策略版本、原因码体系或强验证证明。银行不读3号授权表；内部执行依赖仅服务端持有的令牌边界，生产环境仍应增加网络隔离、轮换和更强执行证明。

## 升级与回滚

启动先执行 `create_all` 添加 `user_phone_registry` 与 `risk_subject_locks`，再扫描旧客户手机号并填充唯一登记；重复运行幂等。非法号码、等价号码被不同客户占用会停止升级，不自动合并。请先停止服务并备份，使用新数据库及模拟旧结构数据库验证。代码回滚不撤销新账务，也不自动反向转账；发生新交易后不可直接覆盖旧备份。账户 Float 字段未迁为整数分，完整对账迁移仍为后续事项。

演示环境尚无生产级号码查询限流、真实号码所有权验证、PostgreSQL/多进程压力验证、真实模型手机号场景联调或真正 MFA。一次性定时转账和 AA 收款仍沿用现有路径；本次两个子功能不等于已完成全部比赛核心场景。
